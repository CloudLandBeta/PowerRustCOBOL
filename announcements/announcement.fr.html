PowerRustCOBOL AI 2 : Web et Mobile

Le COBOL que vous écrivez déjà et le Form Designer que vous utilisez déjà, désormais pour le navigateur et le téléphone.

La version 2 ajoute deux types de projet à côté du projet Desktop : Web et Mobile. Choisissez-en un dans File ▸ New Project. Tous les projets que vous avez écrits auparavant sont des projets Desktop et s’ouvrent sans changement. Voici les nouveautés.

Ce que vous pouvez faire désormais

Applications web

Le Build compile votre COBOL directement en WebAssembly : aucun interpréteur dans la page, et aucune chaîne d’outils Rust nécessaire pour un Build web, car l’IDE copie un lecteur précompilé à côté de votre programme. Le résultat est un paquet statique dans dist/web/ que n’importe quel serveur web peut héberger.

Applications mobiles

Téléphone et tablette Android, iPhone et iPad sous iOS. Run compile, installe et lance l’application sur un téléphone connecté ou un émulateur Android, et affiche son journal dans le panneau Output ; une version de production Android est signée avec votre propre clé. Pour iOS, c’est l’application pour le simulateur qui est compilée aujourd’hui.

Un Backend en COBOL

Les fichiers, les bases de données et les secrets vivent dans le dossier backend/ du projet, sur l’environnement d’exécution natif. La page appelle les programmes que le Backend exporte avec CALL "NAME" WITH WEBSOCKET LINKAGE : du JSON sur TLS avec un jeton bearer, la reconnexion et le renouvellement du jeton étant assurés pour vous. COBOL::SqlDatabase atteint SQLite, PostgreSQL et MySQL sans EXEC SQL.

Connexion et liens

Le contrôle Authentication connecte et inscrit les utilisateurs, récupère un mot de passe et répond à un second facteur, par l’intermédiaire de votre Backend, avec Cognito, Keycloak ou Entra. Le contrôle Hyperlink est un vrai lien dans la page.

CSS3 et pages adaptatives

Une feuille de style d’application et une par formulaire mettent la page en forme, et la feuille de style l’emporte sur une propriété. L’application monopage est le choix par défaut ; les pages de formulaire autonomes sont l’alternative.

Aperçu dans une vue web

Le Preview du concepteur affiche le paquet dans la vue web du système. Choisissez une taille de téléphone, de tablette ou de bureau, l’orientation, la densité de pixels, le schéma de couleurs et la langue de la page ; une modification d’un formulaire, d’une feuille de style ou du Backend parvient à la page ouverte.

Canvas et graphiques

Canvas 2D, Canvas 3D et les objets ImageBuffer, Plot, Scene3D, Physics2D et Physics3D, sur toutes les plateformes.

Sécurisé par défaut

Le Build examine les fichiers de votre projet à la recherche de secrets et s’arrête dès qu’il en trouve un ; le paquet porte une Content-Security-Policy ; un projet Mobile peut épingler des certificats ; un Backend de production refuse un secret écrit en clair dans sa configuration.

Claude Code et Grace connaissent ces types

Le plugin Claude Code compte désormais dix-sept outils et treize skills, dont certains pour les applications web et pour le Backend ; Grace, l’assistante de l’IDE, les connaît, ainsi que COBOL::SqlDatabase.

Le même COBOL en dessous

Le WebAssembly généré est maintenu identique à l’interpréteur par les exécutions de conformité : les modules NC, IF et IC du NIST CCVS85 s’y exécutent sans aucun échec.

Par où commencer

  1. File ▸ New Project, puis choisissez Web (ou un appareil Android ou iOS).
  2. Ouvrez un formulaire et appuyez sur Preview pour le voir dans une vue web.
  3. Ajoutez un programme de Backend, déclarez-le dans backend/exports.toml et appelez-le avec CALL depuis un gestionnaire.
  4. Appuyez sur Build.

Ou ouvrez un exemple depuis File ▸ Open Project :

Portée, en toute franchise. L’archive de production d’une application iOS pour un appareil ou pour la boutique n’est pas encore compilée. La couverture des navigateurs a été mesurée dans Chromium et dans les vues web du système ; Safari sur un Mac et la vue web d’Android sur un téléphone physique n’ont pas encore été mesurés. Le COBOL d’un formulaire web est un sous-ensemble : les fichiers, le SQL et les autres traitements côté serveur relèvent du Backend, et le Build vous indique la ligne qu’il ne peut pas exécuter dans une page. Certains critères d’acceptation des spécifications WebAssembly restent ouverts ; la liste se trouve dans specs/WASM-OPEN-ACS.md.
