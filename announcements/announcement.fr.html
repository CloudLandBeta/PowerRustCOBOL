PowerRustCOBOL AI 2.1 : ce qui est nouveau

Des compilations sans rien installer de plus, et un paquet pour votre serveur. Voici ce qui a changé depuis la 2.0.613, la dernière version publiée.

Six choses valent la peine d’être connues. Le reste tient en une courte liste.

Ce qui est nouveau

Build de bureau sans Rust

Le Build compile votre COBOL en WebAssembly et l’emballe dans un exécuteur déjà compilé : un seul exécutable dans bin/, en une seconde environ pour les projets d’exemple, sans Rust sur votre machine. Un Build de Debug, EXEC RUST, les External Crates et quelques constructions plus rares passent toujours par Cargo ; le Build indique quel chemin il a pris et pourquoi.

Un Backend sans Rust

Le Backend d’un projet Web ou Mobile est construit de la même façon : votre COBOL devient un module WebAssembly qu’un exécuteur déjà compilé sert. Les quatre Backends d’exemple répondent à l’identique par les deux chemins (176 appels, 176 identiques). Le chemin Cargo reste pour ce que le module ne sert pas, et le réglage build_path du Backend peut imposer l’un ou l’autre.

Deux fichiers pour votre serveur

File ▸ Package Project d’un projet Web produit l’application et un script d’installation pour le serveur (.sh sous Linux et macOS, .ps1 sous Windows). Le script prend un seul paramètre, le dossier de nginx, et exécute le Backend comme un service. Avant d’écrire quoi que ce soit, le paquet vérifie vos réglages pour un serveur et prouve que le Backend démarre.

Un paquet pour un autre système

Dans la fenêtre Package, choisissez le System du serveur : aujourd’hui linux-x86_64, depuis un Mac ou une machine Windows, de sorte que vous n’avez plus à empaqueter sur le serveur lui-même. Le Backend de ce paquet est un exécuteur Linux déjà compilé auquel votre module est joint. En ligne de commande : rcrun package --target.

Le Preview garde son adresse

Le Preview et le Run d’un projet Web ou Mobile servent la page toujours sur le même port, si bien qu’un marque-page ou un onglet ouvert la retrouve. Réglez-le dans les paramètres du projet, Page port (Preview) ; la case affiche la valeur par défaut.

Une installation Windows qui vous prépare

L’installation Windows installe les outils de compilation C++ de Microsoft lorsqu’ils manquent et, si vous dites oui sur sa page de préparation, Rust 1.95.0 et les propres éléments de PowerRustCOBOL compilés une seule fois, de sorte que votre premier Build de Debug ne compile que votre programme. Skip installe ce que l’installation a toujours installé.

Changements mineurs

  • Un canvas peut masquer le pointeur de la souris, le ramener en son milieu et signaler Échap : Cursor = None, CenterPointer() et onEscapePressed. PowerCallOfDuty utilise les trois.
  • Un fichier LINE SEQUENTIAL conserve les octets d’un enregistrement tels quels, et le LoadBytes d’un Viewer affiche son document dans le navigateur.
  • Les fichiers nginx qu’écrit le Build d’un projet Web démarrent désormais, servent chaque fichier avec le bon type et conservent les en-têtes de sécurité.
  • Un bouton enfoncé de la barre d’outils paraît enfoncé avec Spatial et les autres thèmes Aurora, et sous macOS le titre des fenêtres de l’IDE reste à côté des boutons de la fenêtre.
  • PowerOficina s’ouvre avec ses données sur une installation propre.
