PowerRustCOBOL AI 2: Web and Mobile

The COBOL you already write and the Form Designer you already use, now for the browser and the phone.

Version 2 adds two project kinds beside the Desktop project: Web and Mobile. Choose one in File ▸ New Project. Every project you wrote before is a Desktop project and opens unchanged. Here is what is new.

What you can do now

Web applications

Build compiles your COBOL straight to WebAssembly: no interpreter in the page, and no Rust toolchain needed for a Web build, because the IDE copies a prebuilt player beside your program. The result is a static bundle in dist/web/ that any web server can host.

Mobile applications

Android phone and tablet, iOS iPhone and iPad. Run builds, installs and starts the app on a connected phone or an Android emulator and shows its log in the Output panel; an Android release is signed with your own key. For iOS the app for the simulator is built today.

A COBOL Backend

Files, databases and secrets live in the project's backend/ folder, on the native runtime. The page calls the programs the Backend exports with CALL "NAME" WITH WEBSOCKET LINKAGE: JSON over TLS with a bearer token, reconnection and token refresh done for you. COBOL::SqlDatabase reaches SQLite, PostgreSQL and MySQL without EXEC SQL.

Sign-in and links

The Authentication control signs users in and up, recovers a password and answers a second factor, through your Backend, with Cognito, Keycloak or Entra. The Hyperlink control is a real link on the page.

CSS3 and responsive pages

An application stylesheet and one per form style the page, and the stylesheet wins over a property. A single-page application is the default; standalone form pages are the alternative.

Preview in a web view

The designer's Preview shows the bundle in the system web view. Pick a phone, tablet or desktop size, the orientation, the pixel ratio, the colour scheme and the page language; a change to a form, a stylesheet or the Backend reaches the open page.

Canvas and graphics

Canvas 2D, Canvas 3D and the ImageBuffer, Plot, Scene3D, Physics2D and Physics3D objects, on every platform.

Secure by default

Build scans your project's own files for secrets and stops on one; the bundle carries a Content-Security-Policy; a Mobile project can pin certificates; a release Backend refuses a literal secret in its configuration.

Claude Code and Grace know the kinds

The Claude Code plugin now has seventeen tools and thirteen skills, including ones for Web applications and the Backend, and Grace, the IDE's assistant, knows them, and COBOL::SqlDatabase too.

The same COBOL underneath

The generated WebAssembly is held equal to the interpreter by the conformance runs: the NIST CCVS85 NC, IF and IC modules run to zero failures on it.

Start here

  1. File ▸ New Project, and choose Web (or an Android or iOS device).
  2. Open a form and press Preview to see it in a web view.
  3. Add a Backend program, list it in backend/exports.toml, and CALL it from a handler.
  4. Press Build.

What each target needs

You buildYou need
a Web applicationnothing beyond the IDE
a Backend release binarythe same toolchain a Desktop Build needs: Rust and the platform linker
an Android packagethe Android SDK and NDK, Java 17 to 21, the Rust target of the phone and the Tauri command line; the Build names each one that is missing
an iOS app for the simulatora Mac with Xcode 16 or later
Honest scope. A release archive of an iOS app for a device or the store is not built yet. Browser coverage has been measured in Chromium and in the system web views; Safari on a Mac and the Android web view on a physical device are not measured yet. A web form's COBOL is a subset: files, SQL and other server-side work belong in the Backend, and the Build tells you the line it cannot run in a page. Some acceptance criteria of the WebAssembly specs are still open; the list is in specs/WASM-OPEN-ACS.md.
