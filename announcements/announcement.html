PowerRustCOBOL AI 2.1: what is new

Builds with nothing extra to install, and one package for your server. This is what changed since 2.0.613, the last published release.

Six things are worth knowing. The rest is a short list.

What is new

Desktop Build without Rust

Build compiles your COBOL to WebAssembly and packs it into a prebuilt runner: one executable in bin/, in about a second for the example projects, with no Rust on your machine. A Debug build, EXEC RUST, External Crates and a few rarer constructs still go through Cargo; the Build says which way it took and why.

A Backend without Rust

A Web or Mobile Backend is built the same way: your COBOL becomes a WebAssembly module that a prebuilt runner serves. The four example Backends answer the same on both ways (176 calls, 176 equal). The Cargo way stays for what the module does not serve, and the Backend setting build_path can force either one.

Two files for your server

File ▸ Package Project of a Web project makes the application and an installer script for the server (.sh on Linux and macOS, .ps1 on Windows). The script takes one parameter, the folder of nginx, and runs the Backend as a service. Before anything is written, the package checks your settings for a server and proves that the Backend starts.

A package for another system

In the Package window, choose the System of the server: today linux-x86_64, made from a Mac or a Windows machine, so you no longer have to package on the server itself. The Backend of that package is a prebuilt Linux runner with your module joined to it. On the command line: rcrun package --target.

The Preview keeps its address

The Preview and the Run of a Web or Mobile project serve the page on the same port every time, so a bookmark or an open tab finds it again. Set it in the project's settings, Page port (Preview); the box shows the default.

A Windows setup that gets you ready

The Windows setup installs Microsoft's C++ build tools when they are missing and, if you say yes on its preparation page, Rust 1.95.0 and PowerRustCOBOL's own parts compiled once, so your first Debug build compiles only your program. Skip installs what the setup always installed.

Smaller changes

  • A canvas can hide the mouse pointer, bring it back to its middle and report Escape: Cursor = None, CenterPointer() and onEscapePressed. PowerCallOfDuty uses all three.
  • A LINE SEQUENTIAL file keeps the bytes of a record as they are, and a Viewer's LoadBytes shows its document in the browser.
  • The nginx files a Web Build writes now start, serve every file with the right type and keep the security headers.
  • A pressed toolbar button looks pressed under Spatial and the other Aurora themes, and on macOS the title of the IDE's windows sits next to the window buttons.
  • PowerOficina opens with its data on a clean install.

What you need

You buildYou need
a Desktop or Web applicationnothing beyond the IDE: the runner is installed beside it
a Debug build, an EXEC RUST block or External CratesRust and the platform linker, as before; on Windows the setup can prepare them
a package for a Linux servera Linux x86-64 server with glibc 2.34 or newer: Debian 12, Ubuntu 22.04 and Amazon Linux 2023 start it; Ubuntu 20.04 and Debian 11 do not
Honest scope. A package for another system exists for Linux x86-64 only (a Windows server's package is still made on Windows), and it was proven in an x86-64 container, not yet on a real server. Build times were measured on a Mac with Apple silicon.
