PowerRustCOBOL AI 2.1：新增内容

无需额外安装即可构建，还能为您的服务器生成一个安装包。以下是自上一个已发布版本 2.0.613 以来的变化。

有六件事值得了解，其余的只是一份简短的清单。

新增内容

不需要 Rust 的桌面 Build

Build 会把您的 COBOL 编译成 WebAssembly，并打包进预先构建好的运行器：在 bin/ 中生成一个可执行文件，示例项目大约一秒即可完成，您的机器上无需安装 Rust。 Debug 构建、EXEC RUST、External Crates 以及少数较罕见的语法结构仍然通过 Cargo；Build 会告诉您它走了哪条路径以及原因。

不需要 Rust 的 Backend

Web 或 Mobile 项目的 Backend 以同样的方式构建：您的 COBOL 变成一个 WebAssembly 模块，由预先构建好的运行器提供服务。 四个示例 Backend 在两条路径上的应答完全一致（176 次调用，176 次相同）。模块不支持的部分仍然走 Cargo 路径， Backend 的设置项 build_path 可以强制选用其中一条。

给服务器的两个文件

Web 项目的 File ▸ Package Project 会生成应用程序和一个服务器安装脚本 （Linux 和 macOS 用 .sh，Windows 用 .ps1）。脚本只接受一个参数，即 nginx 的文件夹， 并把 Backend 作为服务运行。在写出任何文件之前，安装包会检查您针对服务器的设置，并证明 Backend 能够启动。

为另一个系统生成的安装包

在 Package 窗口中选择服务器的 System：目前是 linux-x86_64，可在 Mac 或 Windows 机器上生成，您不再需要到服务器本机上打包。该安装包的 Backend 是预先构建好的 Linux 运行器，并接入了您的模块。 命令行用法：rcrun package --target。

Preview 的地址保持不变

Web 或 Mobile 项目的 Preview 和 Run 每次都在同一个端口上提供页面，因此书签或已打开的标签页可以再次找到它。 请在项目设置的 Page port (Preview) 中指定；输入框会显示默认值。

让您直接就绪的 Windows 安装程序

Windows 安装程序在缺少 Microsoft C++ 生成工具时会安装它们；如果您在准备页面选择“是”，还会一次性编译 Rust 1.95.0 和 PowerRustCOBOL 自身的组件，这样您第一次 Debug 构建时只需编译您自己的程序。选择 Skip 则只安装安装程序一贯安装的内容。

较小的改动

  • 画布可以隐藏鼠标指针、把它移回中心，并报告 Escape 键：Cursor = None、CenterPointer() 和 onEscapePressed。PowerCallOfDuty 同时用到了这三项。
  • LINE SEQUENTIAL 文件会原样保留记录的字节，Viewer 的 LoadBytes 会在浏览器中显示其文档。
  • Web 构建写出的 nginx 文件现在可以正常启动，以正确的类型提供每个文件，并保留安全头。
  • 在 Spatial 及其他 Aurora 主题下，按下的工具栏按钮看起来确实是按下的；在 macOS 上，IDE 窗口的标题位于窗口按钮旁边。
  • 全新安装后，PowerOficina 打开时即带有它的数据。

您需要什么

您要构建您需要
桌面或 Web 应用程序只需 IDE：运行器安装在它旁边
Debug 构建、EXEC RUST 块或 External Crates与以前一样，需要 Rust 和平台链接器；在 Windows 上，安装程序可以帮您准备好
面向 Linux 服务器的安装包glibc 2.34 或更高版本的 Linux x86-64 服务器：Debian 12、Ubuntu 22.04 和 Amazon Linux 2023 可以启动它；Ubuntu 20.04 和 Debian 11 不行
如实说明范围。 面向另一个系统的安装包目前只支持 Linux x86-64（Windows 服务器的安装包仍需在 Windows 上生成）， 并且只在 x86-64 容器中验证过，尚未在真实服务器上验证。构建耗时是在配备 Apple silicon 的 Mac 上测得的。
