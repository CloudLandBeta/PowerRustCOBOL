PowerRustCOBOL AI 2: Web e Mobile

O COBOL que você já escreve e o Form Designer que você já usa, agora para o navegador e para o celular.

A versão 2 adiciona dois tipos de projeto ao lado do projeto Desktop: Web e Mobile. Escolha um em File ▸ New Project. Todo projeto que você escreveu antes é um projeto Desktop e abre sem mudanças. Veja o que há de novo.

O que você já pode fazer

Aplicações web

O Build compila o seu COBOL direto para WebAssembly: sem interpretador na página e sem precisar da cadeia de ferramentas do Rust para um Build web, porque o IDE copia um player pré-compilado para junto do seu programa. O resultado é um pacote estático em dist/web/ que qualquer servidor web pode hospedar.

Aplicações mobile

Celular e tablet Android, iPhone e iPad com iOS. O Run compila, instala e inicia o aplicativo em um celular conectado ou em um emulador Android e mostra o log dele no painel Output; uma versão de lançamento para Android é assinada com a sua própria chave. Para iOS, hoje é compilado o aplicativo para o simulador.

Um Backend em COBOL

Arquivos, bancos de dados e segredos ficam na pasta backend/ do projeto, no runtime nativo. A página chama os programas que o Backend exporta com CALL "NAME" WITH WEBSOCKET LINKAGE: JSON sobre TLS com um token bearer; a reconexão e a renovação do token são feitas para você. COBOL::SqlDatabase acessa SQLite, PostgreSQL e MySQL sem EXEC SQL.

Login e links

O controle Authentication faz login e cadastro de usuários, recupera uma senha e responde a um segundo fator, por meio do seu Backend, com Cognito, Keycloak ou Entra. O controle Hyperlink é um link de verdade na página.

CSS3 e páginas responsivas

Uma folha de estilo da aplicação e uma por formulário estilizam a página, e a folha de estilo prevalece sobre uma propriedade. A aplicação de página única é o padrão; as páginas de formulário independentes são a alternativa.

Preview em uma web view

O Preview do designer mostra o pacote na web view do sistema. Escolha o tamanho de celular, tablet ou desktop, a orientação, a densidade de pixels, o esquema de cores e o idioma da página; uma alteração em um formulário, em uma folha de estilo ou no Backend chega à página aberta.

Canvas e gráficos

Canvas 2D, Canvas 3D e os objetos ImageBuffer, Plot, Scene3D, Physics2D e Physics3D, em todas as plataformas.

Seguro por padrão

O Build examina os arquivos do seu projeto em busca de segredos e para ao encontrar um; o pacote leva uma Content-Security-Policy; um projeto Mobile pode fixar certificados; um Backend de lançamento recusa um segredo escrito literalmente na sua configuração.

O Claude Code e a Grace conhecem os tipos

O plugin do Claude Code agora tem dezessete ferramentas e treze skills, incluindo algumas para aplicações web e para o Backend; a Grace, a assistente do IDE, as conhece, assim como conhece o COBOL::SqlDatabase.

O mesmo COBOL por baixo

O WebAssembly gerado é mantido igual ao interpretador pelas execuções de conformidade: os módulos NC, IF e IC do NIST CCVS85 rodam com zero falhas nele.

Comece por aqui

  1. File ▸ New Project, e escolha Web (ou um dispositivo Android ou iOS).
  2. Abra um formulário e pressione Preview para vê-lo em uma web view.
  3. Adicione um programa de Backend, inclua-o em backend/exports.toml e chame-o com CALL a partir de um handler.
  4. Pressione Build.

Ou abra um exemplo em File ▸ Open Project:

O que cada destino exige

Você compilaVocê precisa de
uma aplicação webnada além do IDE
um binário de lançamento do Backenda mesma cadeia de ferramentas de um Build desktop: Rust e o linker da plataforma
um pacote Androido SDK e o NDK do Android, Java 17 a 21, o alvo Rust do celular e a linha de comando do Tauri; o Build indica cada item que falta
um aplicativo iOS para o simuladorum Mac com Xcode 16 ou posterior
Escopo, com honestidade. O arquivo de lançamento de um aplicativo iOS para um dispositivo ou para a loja ainda não é compilado. A cobertura de navegadores foi medida no Chromium e nas web views do sistema; o Safari em um Mac e a web view do Android em um celular físico ainda não foram medidos. O COBOL de um formulário web é um subconjunto: arquivos, SQL e demais trabalhos do lado do servidor pertencem ao Backend, e o Build informa a linha que não pode ser executada em uma página. Alguns critérios de aceitação das especificações do WebAssembly continuam em aberto; a lista está em specs/WASM-OPEN-ACS.md.
