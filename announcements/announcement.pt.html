PowerRustCOBOL AI 2.1: o que há de novo

Compilações sem instalar mais nada e um pacote para o seu servidor. Isto é o que mudou desde a 2.0.613, a última versão publicada.

Seis coisas merecem a sua atenção. O resto é uma lista curta.

O que há de novo

Build de desktop sem Rust

O Build compila o seu COBOL para WebAssembly e o empacota em um executor já compilado: um único executável em bin/, em cerca de um segundo nos projetos de exemplo, sem Rust na sua máquina. Um Build de Debug, EXEC RUST, as External Crates e algumas construções mais raras continuam passando pelo Cargo; o Build diz qual caminho tomou e por quê.

Um Backend sem Rust

O Backend de um projeto Web ou Mobile é construído do mesmo modo: o seu COBOL vira um módulo WebAssembly que um executor já compilado serve. Os quatro Backends de exemplo respondem igual pelos dois caminhos (176 chamadas, 176 iguais). O caminho do Cargo permanece para o que o módulo não serve, e o ajuste build_path do Backend pode forçar um ou outro.

Dois arquivos para o seu servidor

File ▸ Package Project de um projeto Web gera a aplicação e um script de instalação para o servidor (.sh no Linux e no macOS, .ps1 no Windows). O script recebe um único parâmetro, a pasta do nginx, e executa o Backend como um serviço. Antes de escrever qualquer coisa, o pacote confere os seus ajustes para um servidor e prova que o Backend inicia.

Um pacote para outro sistema

Na janela Package, escolha o System do servidor: hoje linux-x86_64, a partir de um Mac ou de uma máquina Windows, de modo que você não precisa mais empacotar no próprio servidor. O Backend desse pacote é um executor Linux já compilado com o seu módulo unido a ele. Na linha de comando: rcrun package --target.

O Preview mantém o seu endereço

O Preview e o Run de um projeto Web ou Mobile servem a página sempre na mesma porta, e assim um favorito ou uma aba aberta a encontra de novo. Defina-a nos ajustes do projeto, Page port (Preview); a caixa mostra o valor padrão.

Um setup do Windows que deixa você pronto

O setup do Windows instala as ferramentas de compilação C++ da Microsoft quando faltam e, se você disser sim na página de preparação, o Rust 1.95.0 e as partes do próprio PowerRustCOBOL compiladas uma única vez, de modo que o seu primeiro Build de Debug compila só o seu programa. Skip instala o que o setup sempre instalou.

Mudanças menores

  • Um canvas pode esconder o ponteiro do mouse, trazê-lo de volta ao seu centro e avisar do Escape: Cursor = None, CenterPointer() e onEscapePressed. O PowerCallOfDuty usa os três.
  • Um arquivo LINE SEQUENTIAL guarda os bytes de um registro como estão, e o LoadBytes de um Viewer mostra o seu documento no navegador.
  • Os arquivos do nginx que o Build de um projeto Web escreve agora iniciam, servem cada arquivo com o tipo certo e mantêm os cabeçalhos de segurança.
  • Um botão pressionado da barra de ferramentas aparece pressionado no Spatial e nos outros temas Aurora, e no macOS o título das janelas do IDE fica ao lado dos botões da janela.
  • O PowerOficina abre com os seus dados em uma instalação limpa.

O que você precisa

Você compilaVocê precisa de
uma aplicação desktop ou Webnada além do IDE: o executor é instalado ao lado dele
um Build de Debug, um bloco EXEC RUST ou External CratesRust e o linker da plataforma, como antes; no Windows o setup pode prepará-los
um pacote para um servidor Linuxum servidor Linux x86-64 com glibc 2.34 ou mais nova: Debian 12, Ubuntu 22.04 e Amazon Linux 2023 o iniciam; Ubuntu 20.04 e Debian 11 não
Escopo, com honestidade. Um pacote para outro sistema existe só para Linux x86-64 (o pacote de um servidor Windows continua sendo feito no Windows), e foi provado em um contêiner x86-64, ainda não em um servidor real. Os tempos de compilação foram medidos em um Mac com Apple silicon.
