PowerRustCOBOL AI 2: Web y Móvil

El COBOL que ya escribes y el Form Designer que ya usas, ahora para el navegador y el teléfono.

La versión 2 añade dos tipos de proyecto junto al proyecto Desktop: Web y Mobile. Elige uno en File ▸ New Project. Todos los proyectos que escribiste antes son proyectos Desktop y se abren sin cambios. Esto es lo nuevo.

Lo que ya puedes hacer

Aplicaciones web

Build compila tu COBOL directamente a WebAssembly: sin intérprete en la página y sin necesidad de la cadena de herramientas de Rust para un Build web, porque el IDE copia un reproductor precompilado junto a tu programa. El resultado es un paquete estático en dist/web/ que cualquier servidor web puede alojar.

Aplicaciones móviles

Teléfono y tableta Android, iPhone y iPad con iOS. Run compila, instala e inicia la aplicación en un teléfono conectado o en un emulador Android y muestra su registro en el panel Output; una versión de lanzamiento para Android se firma con tu propia clave. Para iOS, hoy se compila la aplicación para el simulador.

Un Backend en COBOL

Los archivos, las bases de datos y los secretos viven en la carpeta backend/ del proyecto, sobre el entorno de ejecución nativo. La página llama a los programas que exporta el Backend con CALL "NAME" WITH WEBSOCKET LINKAGE: JSON sobre TLS con un token bearer; la reconexión y la renovación del token las hace el sistema por ti. COBOL::SqlDatabase llega a SQLite, PostgreSQL y MySQL sin EXEC SQL.

Inicio de sesión y enlaces

El control Authentication inicia sesión y registra usuarios, recupera una contraseña y responde a un segundo factor, a través de tu Backend, con Cognito, Keycloak o Entra. El control Hyperlink es un enlace de verdad en la página.

CSS3 y páginas adaptables

Una hoja de estilo de la aplicación y una por formulario dan estilo a la página, y la hoja de estilo prevalece sobre una propiedad. La aplicación de una sola página es la opción predeterminada; las páginas de formulario independientes son la alternativa.

Vista previa en una vista web

La Preview del diseñador muestra el paquete en la vista web del sistema. Elige un tamaño de teléfono, tableta o escritorio, la orientación, la densidad de píxeles, el esquema de color y el idioma de la página; un cambio en un formulario, una hoja de estilo o el Backend llega a la página abierta.

Canvas y gráficos

Canvas 2D, Canvas 3D y los objetos ImageBuffer, Plot, Scene3D, Physics2D y Physics3D, en todas las plataformas.

Seguro por defecto

Build revisa los archivos de tu proyecto en busca de secretos y se detiene si encuentra uno; el paquete lleva una Content-Security-Policy; un proyecto Mobile puede fijar certificados; un Backend de lanzamiento rechaza un secreto escrito literalmente en su configuración.

Claude Code y Grace conocen los tipos

El complemento de Claude Code tiene ahora diecisiete herramientas y trece habilidades, entre ellas algunas para aplicaciones web y para el Backend, y Grace, la asistente del IDE, las conoce, y COBOL::SqlDatabase también.

El mismo COBOL por debajo

El WebAssembly generado se mantiene igual al intérprete mediante las pruebas de conformidad: los módulos NC, IF e IC de NIST CCVS85 se ejecutan con cero fallos sobre él.

Empieza aquí

  1. File ▸ New Project, y elige Web (o un dispositivo Android o iOS).
  2. Abre un formulario y pulsa Preview para verlo en una vista web.
  3. Añade un programa de Backend, inclúyelo en backend/exports.toml y llámalo con CALL desde un manejador.
  4. Pulsa Build.

O abre un ejemplo desde File ▸ Open Project:

Lo que necesita cada destino

CompilasNecesitas
una aplicación webnada más que el IDE
un binario de lanzamiento del Backendla misma cadena de herramientas que un Build de escritorio: Rust y el enlazador de la plataforma
un paquete Androidel SDK y el NDK de Android, Java 17 a 21, el destino de Rust del teléfono y la línea de comandos de Tauri; el Build nombra cada pieza que falta
una aplicación iOS para el simuladorun Mac con Xcode 16 o posterior
Alcance, con honestidad. Todavía no se compila un archivo de lanzamiento de una aplicación iOS para un dispositivo o para la tienda. La cobertura de navegadores se ha medido en Chromium y en las vistas web del sistema; Safari en un Mac y la vista web de Android en un teléfono físico aún no se han medido. El COBOL de un formulario web es un subconjunto: los archivos, el SQL y demás trabajo del lado del servidor corresponden al Backend, y el Build te indica la línea que no puede ejecutarse en una página. Algunos criterios de aceptación de las especificaciones de WebAssembly siguen abiertos; la lista está en specs/WASM-OPEN-ACS.md.
