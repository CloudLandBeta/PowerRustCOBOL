PowerRustCOBOL AI 2.1: qué hay de nuevo

Compilaciones sin instalar nada más y un paquete para tu servidor. Esto es lo que cambió desde la 2.0.613, la última versión publicada.

Seis cosas merecen tu atención. El resto es una lista corta.

Qué hay de nuevo

Build de escritorio sin Rust

Build compila tu COBOL a WebAssembly y lo empaqueta en un ejecutor ya compilado: un único ejecutable en bin/, en alrededor de un segundo para los proyectos de ejemplo, sin Rust en tu equipo. Un Build de Debug, EXEC RUST, las External Crates y algunas construcciones poco frecuentes siguen pasando por Cargo; el Build te dice qué camino tomó y por qué.

Un Backend sin Rust

El Backend de un proyecto Web o Mobile se construye igual: tu COBOL se convierte en un módulo WebAssembly que sirve un ejecutor ya compilado. Los cuatro Backends de ejemplo responden igual por ambos caminos (176 llamadas, 176 iguales). El camino de Cargo se mantiene para lo que el módulo no sirve, y el ajuste build_path del Backend puede forzar uno u otro.

Dos archivos para tu servidor

File ▸ Package Project de un proyecto Web genera la aplicación y un script de instalación para el servidor (.sh en Linux y macOS, .ps1 en Windows). El script recibe un solo parámetro, la carpeta de nginx, y ejecuta el Backend como un servicio. Antes de escribir nada, el paquete revisa tus ajustes para un servidor y comprueba que el Backend arranca.

Un paquete para otro sistema

En la ventana Package elige el System del servidor: hoy linux-x86_64, desde un Mac o un equipo con Windows, de modo que ya no tienes que empaquetar en el propio servidor. El Backend de ese paquete es un ejecutor de Linux ya compilado con tu módulo unido a él. En la línea de comandos: rcrun package --target.

El Preview conserva su dirección

El Preview y el Run de un proyecto Web o Mobile sirven la página siempre en el mismo puerto, así que un marcador o una pestaña abierta la vuelve a encontrar. Se define en los ajustes del proyecto, Page port (Preview); la casilla muestra el valor por defecto.

Una instalación de Windows que te deja listo

La instalación de Windows instala las herramientas de compilación de C++ de Microsoft cuando faltan y, si dices que sí en su página de preparación, Rust 1.95.0 y las piezas propias de PowerRustCOBOL compiladas una sola vez, de modo que tu primer Build de Debug compila solo tu programa. Skip instala lo que la instalación siempre instaló.

Cambios menores

  • Un canvas puede ocultar el puntero del ratón, devolverlo a su centro e informar de Escape: Cursor = None, CenterPointer() y onEscapePressed. PowerCallOfDuty usa los tres.
  • Un archivo LINE SEQUENTIAL conserva los bytes de un registro tal cual, y el LoadBytes de un Viewer muestra su documento en el navegador.
  • Los archivos de nginx que escribe el Build de un proyecto Web ahora arrancan, sirven cada archivo con el tipo correcto y conservan las cabeceras de seguridad.
  • Un botón pulsado de la barra de herramientas se ve pulsado con Spatial y con los demás temas Aurora, y en macOS el título de las ventanas del IDE queda junto a los botones de la ventana.
  • PowerOficina se abre con sus datos en una instalación limpia.

Lo que necesitas

Tú compilasNecesitas
una aplicación de escritorio o Webnada más que el IDE: el ejecutor se instala a su lado
un Build de Debug, un bloque EXEC RUST o External CratesRust y el enlazador de la plataforma, como antes; en Windows la instalación puede prepararlos
un paquete para un servidor Linuxun servidor Linux x86-64 con glibc 2.34 o posterior: Debian 12, Ubuntu 22.04 y Amazon Linux 2023 lo arrancan; Ubuntu 20.04 y Debian 11 no
Alcance, con honestidad. Un paquete para otro sistema existe solo para Linux x86-64 (el paquete de un servidor Windows se sigue haciendo en Windows), y se probó en un contenedor x86-64, todavía no en un servidor real. Los tiempos de compilación se midieron en un Mac con Apple silicon.
