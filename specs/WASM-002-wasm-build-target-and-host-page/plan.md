# Plan — WebAssembly build target and host page (WASM-002)

- **Status:** revised 2026-10-22 against the spec as it stands after the operator's answers of 2026-10-22 (commit `79400bd9`). The
  bundle assembler, the CSP, the secret scan, the size report and the dev server stay as built and measured on 2026-10-20; the
  host page's JavaScript moves from hand-written files to Build-generated output (Q6); the IDE's Build path (R1, R3, R9), which
  the previous revision handed to "IDE-side specs" that do not own it, is now planned here. Mobile (R2) stays WASM-012's.
- **Spec:** ./spec.md   **Date:** 2026-10-22 (first revision 2026-10-20)

Tools recorded on 2026-10-20 (not re-measured for this revision): rustc 1.95.0 stable; `nightly-2026-10-08` for the threaded
player only; `wasm-bindgen` 0.2.129; `wasm-opt` 133; node v23.3.0; Chrome 152.0.7977.149. The nightly is superseded by the

## 1. Approach

Two layers, each with one owner:

1. **`crates/cobolt-web-bundle`** — a **pure function** `assemble_bundle(&BundleInput) -> Result<BundleOutput, BundleError>`
   (`src/lib.rs:415`): program modules (multi- and single-memory), sanitised forms, menus, stylesheet, assets and the player in →
   the files of a static site plus a `BuildReport` (`lib.rs:231`) out. No toolchain runs there. **New:** it also *writes the host
   page's code* (C1) instead of copying fixed files.
2. **`crates/cobolt-project-tools/src/web/build.rs`** (new) — the **real `WebBuildBackend`** (C6): project → generated COBOL →
   front end → portability refusals → `cobolt-wasm` → `assemble_bundle` → atomic replace of `dist/web`. Linked once at program start
   where `web::link`'s doc comment says (`web/mod.rs:276-278`: the IDE's `main`, `rcrun`'s `mcp` command), so the IDE's Build button,
   its Preview (WASM-008) and the agents' `build` tool get it with no screen change.

Per requirement:

- **R1, R16, R17 — the bundle.** `WasmBuild::build(&WebBuildRequest)`:
  1. For each form in `request.forms` (`web/mod.rs:56`): load the `.cfrm`/`.wcfrm`/`.mcfrm` with `cobolt-forms`, produce its COBOL with
     `cobolt_codegen::generate_with_map` (`cobolt-codegen/src/lib.rs:356`, which also returns the `SourceMap` that R3 needs to point at the
     developer's handler line) — the generated-code contract unchanged: the same text the desktop Build regenerates on action.
  2. Lex, parse and run `cobolt-semantic` on it with the Common Code of `request.sources`, exactly as the desktop Build does; a semantic
     error stops the build as it does there.
  3. Build one `cobolt_wasm::module::FormSpec` (`module.rs:141`) per form and call `compile_project` (`module.rs:161`) once per variant
     in `request.variants` (`ModuleVariants`, `cobolt-compiler/src/project_kind.rs:257`), with `Options { multi_memory, conformance: false,
     tolerate_undeclared: false, … }` (`module.rs:51-66`). One module for the whole project (WASM-017 R1).
  4. Take the player from the committed `assets/web-player/` (`plain/`, `threaded/`, `parts/*`, `player-build.json`, all tracked) — or the
     **pinned older player** when the project pins one (WASM-016 R11, Q6 decided); a pin the compiler can no longer emit for is a build
     error naming the version. The lookup reuses the IDE's existing bundled-asset resolution (WASM-016 R12); the exact function is fixed at
     `/tasks` after reading it (not named here because it was not read for this plan).
  5. `assemble_bundle`, then write the files to a sibling temporary folder and **rename it over `dist/web`** — the atomic-replace contract
     documented on the trait (`web/mod.rs:236-239`); a failed build leaves the previous bundle in place.
  6. Map `cobolt_web_bundle::BuildReport` onto `cobolt_project_tools::web::BuildReport` (`web/mod.rs:164`): sizes, warnings, duration.
  Standalone style already writes one entry page per form (`lib.rs:736-741`); SPA one `index.html` and the player's router (WASM-011). The
  assembler adds no interpreter, AST or runtime (R16); AC4b's import-section check is a test here (§6), the module's content is WASM-010's.
- **R3 — portable subset at Check and Build.** **One source of refusals: the generator** (R3 last sentence, WASM-010 R8). `GenError`
  (`cobolt-wasm/src/error.rs:12`) already carries every refusal with its line (`all()`, `:26`). The backend maps each through the
  `SourceMap` to `file:line: construct — alternative` and returns `WebBuildError::Refused` (`web/mod.rs:200`), which the IDE's Preview
  already displays (`panels/web_preview.rs:653`). **Check** on a Web or Mobile project runs steps 1–3 and discards the bytes (seconds,
  no file written) so Check and Build cannot disagree. The refused list per R3: file organisations on disk, the disk indexed engines and
  `redb`, child processes, OS threads, native sockets, SQL, `EXEC RUST`, embedded secrets. **Portable** per the amended R3: `INDEXED`
  with `STORAGE IS MEMORY` (`StorageMode`, `cobolt-ast/src/program.rs:114`) and `SORT`/`MERGE` in memory. Whether each refusal message
  names an alternative is asserted by a test (R3 requires it; `GenError`'s comment says "where there is one").
  *Working assumption, to confirm:* a `STORAGE IS MEMORY` file declared `WITH PERSISTENCE` (`program.rs:117-120`: written to its disk
  container on `CLOSE`) **needs the local disk** and is refused under R3's first clause; the spec does not say so in words.
- **R4 — behaves as on the desktop.** Measured by WASM-010 R16 and AC7–AC8 (the parity harness and NIST); this plan adds nothing of its own
  beyond pointing AC4 there, as the spec does.
- **R5 — DOM, not canvas.** The player's (WASM-016); nothing in the bundle draws.
- **R6 — tools.** A Web build calls no external program: steps 1–6 are in-process Rust. Proved by a test that runs the build with an empty
  `PATH` (AC6, Web half). The Mobile tools (Tauri 2 CLI, Android SDK/NDK, Xcode, Rust) are detected and offered by WASM-012's shell build,
  reusing `crates/cobolt-ide/src/toolchain.rs` (`detect` `:204`, `install_argv` `:327`) for the Rust part; R6's "`rustup target add` may be
  installed after the developer agrees, Xcode and the Android SDK may not" is WASM-012's to implement.
- **R7 — no secret.** `secrets.rs` as built: known shapes are **errors** naming file and pattern, never the value; high-entropy strings are
  **warnings** (WASM-013 Q3 decided: the recommendation — which is what the code does, `lib.rs:772-782`). A release build refuses
  `skip_secret_scan` (`lib.rs:468-470`). The `.wcfrm`/`.mcfrm` extensions are missing from `secrets::is_text_path` (`secrets.rs:259`);
  WASM-001's plan adds them — this plan's Build depends on it and its AC5 test plants the key in a `.wcfrm`.
- **R8 — sizes.** The report lists player variants, each part (and which load on first use), the modules, loader, stylesheet and assets
  (as built). **New (C4):** one line comparing the first download — program module(s) the probe can pick, plain player, loader, page,
  stylesheet — with a **5 MB budget**, a **warning** when over. *Open (Q5):* whether 5 MB caps the first download or the whole bundle,
  whether MB is 10⁶ or 2²⁰ bytes, and the first-paint target. Until the operator confirms, it never fails a build.
- **R9 — Desktop unchanged.** No file of the desktop path is touched: `cobolt-compiler`'s `build_project`, `bin/`, eframe and the host-triple
  rule. The new backend is reached only through `WebBuildRequest::from_manifest`, which refuses a Desktop project (`web/mod.rs:73-78`).
- **R10–R13, R15 — the host page.** Behaviour as built: fill the viewport (dynamic viewport units) or mount into the element named by
  `Embed::Element { selector }` (`lib.rs:56`) inside a **shadow root** so CSS leaks neither way while CSS custom properties pass in; a
  `ResizeObserver` on the element re-lays out and drives the breakpoints from the element's width; the surface is `mount`, `unmount`,
  start parameters, `settled()` and the events of R13; progress while loading; a readable message and a retry instead of a blank page.
  **What changes is where the code comes from (C1, §4.1).**
- **R14 — CSP.** `csp.rs` as built: `script-src 'self' 'wasm-unsafe-eval'` (`csp.rs:73`), never `'unsafe-eval'` or `'unsafe-inline'`;
  `connect-src` the configured backends only; `img-src` the configured origins; the reCAPTCHA prefixes only with a site key.
  **Trusted Types are best effort** (WASM-013 Q2 decided): `require-trusted-types-for 'script'` with a default policy is emitted
  (`csp.rs:88-89`) and is enforced where the browser supports it; a browser without Trusted Types is not refused. The Build prints the
  policy (`BuildReport.csp_meta`, `csp_header`).
- **R18, R19 — features, variants, streaming.** As built: `WebAssembly.validate` of small modules for the baseline (bulk memory, mutable
  globals, sign extension, non-trapping float-to-int, reference types, multi-value) and for multi-memory; the program variant, the player
  variant and the execution mode chosen independently; `instantiateStreaming` with an integrity digest; parts on first use. **Adopted:**
  the browser matrix is **versions released from 2024 onwards** (WASM-017 Q4 decided); the generated loader carries that matrix's baseline
  and names it in the R15 message. Variants emitted follow `WebSettings::module_variants` (`project_kind.rs:310-315`): single-memory whenever
  multi-memory is off or the matrix includes Safari or the iOS web view.
- **R20 — threads when isolated.** As built: `_headers`, `hosting/nginx.conf`, `hosting/.htaccess` (`csp.rs:178-198`) and the dev server
  carry `COOP: same-origin` + `COEP: require-corp | credentialless` from `Isolation` (`project_kind.rs:170-212`); the **service-worker shim is
  offered**, off by default (WASM-017 Q10 decided; `BundleOptions.service_worker_shim`, `lib.rs:151`). **Adopted:** the default Worker count is
  `hardwareConcurrency − 1`, capped at 8 (WASM-017 Q2 decided), written by the generated loader when `BundleOptions.workers` is `None`.
  Embedded in a non-isolated page → plain player, main thread, reason reported.

- `config.json` (loader ⇄ assembler) is unchanged in shape; it gains no key for C1. Its keys stay documented in `lib.rs`.
- `BuildReport` (bundle) gains a budget line; `cobolt_project_tools::web::BuildReport` carries it in `warnings` (no new field).

## 4. Key decisions & alternatives

### 4.1 The host page's code is generated by Rust at every Build (Q6, C1)

- **Decision:** `hostpage.rs` writes each JavaScript file from Rust at Build time. Every emitted file begins with the banner
  `// Generated by PowerRustCOBOL AI at Build. Do not edit: it is written again at every Build.` (`<!-- … -->` for the page, `/* … */` for the
  stylesheet) — no "cobolt", no timestamp, so the output stays deterministic and content-hashed. The bundle is regenerated at every Build
  like every generated artefact.
- **Why:** Q6's ruling; WASM-013 R9 (no package-manager tree, nothing hand-edited); the PRIME DIRECTIVE (no tracked non-Rust source).
- **Rejected:** keeping the `.js` files and calling the `include_str!` copy "generated" — they would still be hand-edited, tracked JavaScript.
  Rejected: a JavaScript minifier or bundler — a tool and a dependency tree for a few hundred lines.
- **Boundary stated:** the committed `assets/web-player/**/*.js` are `wasm-bindgen` **outputs** of the product's build, committed as
  `chunked.data` is (WASM-016 Q2 decided) and guarded by the player's freshness test — build artefacts, not source.

### 4.2 The Build lives in `cobolt-project-tools` behind the existing trait (C6)

- **Decision:** implement `WebBuildBackend` in `cobolt-project-tools`, link it at the two start points.
- **Why:** the trait, the request, the dev server and the Preview seam are already there and already consumed by the IDE and the agents'
  tools; one implementation serves all three.
- **Rejected:** putting it in `cobolt-compiler` (it would make the desktop compiler depend on the WebAssembly generator and widen R9's
  blast radius); a new crate (a third place for one function).

### 4.3 Check and Build share one refusal source (R3)

- **Decision:** Check runs the generator and discards the bytes.
- **Rejected:** a separate portability linter in `cobolt-semantic` — two lists that drift, against R3's "the generator is where they are refused".

### 4.4 `cargo-leptos` stays out of the developer's Web build (Q2, C2)

- **Decision:** the developer's Web Build runs no Cargo command; `cargo-leptos` is a product-build tool (WASM-017 R17) and the backend's
  (WASM-003 R2). **Consequence stated:** the player today is plain Rust over `web-sys`, with no `leptos` dependency
  (`crates/cobolt-web-player/Cargo.toml`); WASM-016's plan §4 records that deviation. Aligning the player with the ruling is WASM-016's
  work. This spec depends only on the player's files and ABI v1, so neither outcome changes this plan.

### 4.5 Kept from 2026-10-20

- `coi-serviceworker` as the fallback for hosts that cannot set headers, off by default; headers preferred.
- A part is loaded with the same integrity checks as the player; a failed part may be asked for again.
- Isolation headers written for Netlify/Cloudflare (`_headers`), nginx and Apache, and served by the dev server.

### 4.6 Rulings from other specs adopted here

| Ruling | Where it lands |
|---|---|
| WASM-013 Q2: Trusted Types best effort | CSP keeps the directive; no refusal of browsers without it |
| WASM-013 Q3: entropy = warning, known shapes = error | as built |
| WASM-016 Q6 / R11: current player by default, a project may pin an older one | Build step 4 |
| WASM-017 Q2: Workers = `hardwareConcurrency − 1`, max 8 | generated loader default |
| WASM-017 Q4: browsers released from 2024 onwards | the declared matrix and the R15 message |

## 5. Risks & mitigations

- **Rewriting the loader as Rust-emitted text breaks a behaviour the e2e scenarios do not cover.** → Step 1 of the move emits text
  byte-identical to today's files (a test compares them while both exist); only then are the files deleted and per-build values written
  in directly. The 14 node scenarios and the Chrome runs are re-run on the generated output.
- **The generator refuses constructs the desktop accepts that a real project uses** (coverage, not portability). → Those surface as
  `Refused` lines with the construct named; they are WASM-010's backlog, never silently skipped. The Build never falls back to anything.
- **A refusal without an alternative** violates R3. → A test walks every refusal message the generator can raise for the R3 list.
- **The budget's unit and scope are unconfirmed.** → Warning only; the number and what it covers are one constant until Q5 is confirmed.
- **Persistence on a MEMORY file** (working assumption: refused) may be wrong. → Flagged in §7; one refusal rule to flip.
- **`cobolt-wasm` in the IDE's dependency graph** adds build time. → `default-features = false` (no `wasmi`); measured at `/tasks`.
- **A browser lacks a baseline feature / a host strips headers / a deploy races a cached name** → kept from 2026-10-20: readable refusal,
  plain-player fallback with its reason, content-addressed names.
- **Only Chrome measured.** → Firefox, Safari, iOS web view and Android WebView are not installed here; their matrix cells are listed as
  owed, with the commands, never claimed.

## 6. Test strategy

Existing, kept (as of 2026-10-20): `cargo test -p cobolt-web-bundle` — 18 unit tests (`secrets.rs` 7, `csp.rs` 5, `hash.rs` 3,
`devserver.rs` 3), `csp_origins` 2, `no_string_execution` 3, `e2e_node` (14 node scenarios: variant choice by probe, the fixed-memory core

New, each reporting what it asserted:

- `cobolt-web-bundle/tests/generated_host_page.rs` — (a) every emitted `.js`, the page and the stylesheet start with the banner;
  (b) two builds of the same input give byte-identical files (determinism, hashes stable); (c) `crates/cobolt-web-bundle` contains no
  `.js`/`.html`/`.css` source (a guard against the files coming back); (d) during the move only: generated text equals the old files.
- `no_string_execution.rs` — the same bans (`eval`, `new Function`, string `setTimeout`, `innerHTML` …) applied to the **generated** output
  of the reference bundles, threaded glue and `workerHelpers.js` included.
- `cobolt-project-tools/tests/web_build.rs` — a hello-world Web project built through `WasmBuild`: `dist/web` holds `index.html`, the
  modules for the variants `module_variants` asks for, the player, `config.json`, `_headers`; each module's import section lists only ABI v1
  §3 imports (**AC4b**); no file is an interpreter, AST blob or runtime library (**AC4b**); a failed second build leaves the first bundle intact
  (atomic replace); a Desktop manifest is refused before anything is written (**R9**).
- Same file — **AC3**: a form handler with `OPEN INPUT` of a disk file → `Refused` with the `.wcfrm` handler line, the construct and an
  alternative; `dist/web` not written; Check returns the same lines. `STORAGE IS MEMORY` INDEXED and an in-memory `SORT` build (**C5**).
- Same file — **AC5**: a deliberate test key in a `.wcfrm` property stops the Build naming the file and pattern, never the value
  (with WASM-001's extension change).
- Same file — **AC6, Web half**: the build succeeds with `PATH` emptied for the process. The Mobile half is WASM-012's.
- **AC8**: `cargo test -p cobolt-compiler` and the desktop build tests re-run green, `--no-fail-fast`, every `test result` line read.
- **AC1 / AC2**: the hello-world bundle from `WasmBuild` (not only the fixture module) served by `examples/serve.rs`, a button click
  answered under node and in Chrome; mounted into one `<div>` beside other content, computed styles asserted on both sides, resize of the
  element followed. **AC4** is WASM-010's parity gate. **AC7** is WASM-012's.
- Measured numbers kept from 2026-10-20 (Chrome 152, 127.0.0.1): main-thread yield over 12 runs, 384 timer samples — p50 4.8 ms, p95 5.2,
  p99 6.1, max 6.9; data memory 64 KiB and arena 1 MiB unchanged after 100 open/close cycles plus 1,000 writes. Re-run on the generated
  loader before claiming them for this revision.
- **Not measurable here:** Firefox, Safari (desktop, iOS), Android WebView — not installed; the single-memory fallback is proved by the
  probe's logic and by running the single-memory variant under node and Chrome.
- Manual: in the IDE, Build a Web project from the Web template → the Output shows the size report with the budget line; Preview shows the
  form. (Through the PowerRustCOBOL MCP tools, not by driving the window.)

## 7. Steering compliance and open points

- [ ] i18n: the new IDE strings (budget warning, Check heading, pinned-player error) in all 6 languages; generator diagnostics stay English
  like every compiler diagnostic; the loader's own messages are the *application's* texts (`BundleOptions.texts`), English by default.
- [x] Generated-code contract: the generated COBOL and its banner are unchanged; the host page's code becomes a generated artefact with its
  own banner, regenerated at every Build, never hand-edited (Q6).
- [x] PRIME DIRECTIVE: the tracked JavaScript, HTML and CSS sources of this crate are removed; the remaining `.js` in the tree are committed
  build outputs of the player (§4.1).
- [x] `README.md` and `docs/` untouched; what 2.x.x says about itself stays in `specs/`.
- [ ] System KB: no control, property, method or event is added. The portable-subset list Grace must know is assigned by §6 of the spec to
  the documentation/KB spec (WASM-015/WASM-028); if `/tasks` changes a refusal message that a compiler doc table quotes, that table and
  `assets/knowledge/chunked.data` are regenerated in the same change.
- [x] Interpreter/binary parity: no runtime change; the browser module is held equal by WASM-010 R16.
