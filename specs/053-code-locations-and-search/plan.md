# Plan — Code locations: precise diagnostics and project-wide code search

- **Status:** draft → approved
- **Spec:** ./spec.md   **Date:** 2026-08-23

## 1. Approach

The spec asks for two features that both need one missing thing: an address for
a place a developer writes COBOL, and a way to get from a generated line back to
it. The design is therefore three layers, bottom-up, each usable on its own.

**Layer 1 — the address (R1–R5).** `CodeSite` lands in `cobolt-forms` beside the
model it addresses, *not* in the IDE, so `rcrun check` can report sites later
without a second definition. One function, `code_sites(&Form)`, yields every site
and its text; it is the single source of truth for "what a site is", used by both
the map and the search, so the two cannot disagree about the taxonomy. The five
fixed sections already have an enumeration to reuse —
`panels::cobol_structure::SECTIONS` / `CsTarget` — which is lifted into the model
crate so the IDE's editor targets and the model's sites are the same list.

**Layer 2 — the map (R6–R9).** Codegen *already* returns a partial map:
`generate_with_user_lines(&Form) -> (String, Vec<(u32,u32)>)`
([lib.rs:117](crates/cobolt-codegen/src/lib.rs:117)) records the line ranges of
developer-authored handler and procedure bodies, for the debugger. It is the
right seam and the wrong payload: it covers only bodies with a `PROGRAM-ID`, and
a range says *that* a line is user code, not *whose* or *which line of theirs*.

We widen the payload, not the mechanism: `generate_with_map` becomes the
primitive returning `(String, SourceMap)`, and both `generate` and
`generate_with_user_lines` become thin wrappers over it — the latter deriving its
`Vec<(u32,u32)>` from the map. Every existing consumer (the debugger,
`agent_lint::compile_defects`) keeps compiling and behaving identically (R29).
Because only the *recording* changes and never a `push_str`, the generated bytes
cannot move (R8).

Three writers need to record, and the threading already exists (`user_lines: &mut
…` becomes `map: &mut SourceMap`):

| Site kind | Writer | State today |
|---|---|---|
| SPECIAL-NAMES · REPOSITORY · FILE-CONTROL · FILE SECTION | `weave_block` | one chokepoint, records nothing |
| WORKING-STORAGE | the `user_ws_source` loop in `write_data_division` ([lib.rs:542](crates/cobolt-codegen/src/lib.rs:542)) | records nothing; **skips leading blank lines** |
| Control/form handlers · user procedures | the body loop at [lib.rs:1989](crates/cobolt-codegen/src/lib.rs:1989) | already computes `body_start`/`body_end`; needs the site identity |

**Layer 3 — the two features.** `DiagMsg` gains an `origin`, the Output panel
renders and activates it, one `goto_code_location` does all navigation, and the
search panel enumerates `code_sites` across the project and reuses the same
navigation. Search and diagnostics share the jump — there is one way to land on a
line, not two.

`agent_lint::attribute` ([agent_lint.rs:235](crates/cobolt-ide/src/agent_lint.rs:235))
is deleted and re-pointed at the map. It currently recovers the owning operation
by scanning *backwards through the generated text* for the nearest `PROGRAM-ID.`
— a heuristic that cannot see a structure section at all (they have no
`PROGRAM-ID`) and would silently mis-attribute if codegen ever reorders. The map
answers exactly and for every site kind.

## 3. Data / model changes

```rust
// cobolt-forms
pub enum StructureSection { SpecialNames, Repository, FileControl, FileSection, WorkingStorage }

pub enum CodeSite {
    ControlEvent { control_id: String, event: String },
    FormEvent    { event: String },
    Procedure    { name: String },
    Section      (StructureSection),
    CommonCode   { rel_path: String },   // no owning form
}

// cobolt-codegen
pub struct MappedSpan {
    site: CodeSite,
    gen_start: u32, gen_end: u32,   // 1-based inclusive, in the generated .cbl
    site_line_at_start: u32,        // which line OF THE SITE gen_start holds
}
pub struct SourceMap { spans: Vec<MappedSpan> }
impl SourceMap { pub fn resolve(&self, gen_line: u32) -> Option<(&CodeSite, u32)>; }
```

`site_line_at_start` is not decoration: the WORKING-STORAGE weaver drops leading
blank lines, so generated line *N* is **not** site line *N − gen_start + 1*. The
field records the true offset once, per span, instead of every consumer
re-deriving a rule it will get wrong.

- **`.cfrm` schema: unchanged.** No new persisted form data.
- **Generated `.cbl`: unchanged, byte for byte** (R8) — the map is a return
  value, never text in the file.
- **`SourceMap` derives serde** so a later runtime-locations spec can ship it
  into a compiled binary without a retrofit (spec Q6).
- **Migration: none.** Everything is derived at generate time from data that
  already exists.

## 4. Key decisions & alternatives

- **Decision: widen `generate_with_user_lines` rather than add a parallel API.**
  Why: one recording path means the debugger's view of "user code" and the
  diagnostics' view are the same fact. Rejected: a second `source_map()` pass
  that re-derives ranges — two derivations of one truth is precisely how this
  codebase has repeatedly ended up with painters that disagree.

- **Decision: `CodeSite` in `cobolt-forms`, not `cobolt-ide`.** Why: `rcrun
  check` should eventually report sites too, and `structure.md` puts model
  changes in `cobolt-forms`. Rejected: defining it in the IDE — it would have to
  be duplicated or moved the moment the CLI wants it.

- **Decision: `code_sites()` is the one enumeration; `CsTarget` maps onto it.**
  Why: the IDE already enumerates the five sections in `SECTIONS`; a second list
  in the search would drift the first time a section is added. Rejected: letting
  the search hard-code its own list of places to look.

- **Decision (spec Q1, operator ruling): the search lives in its own window**
  (R32), not a dock panel. Why: its layout then owes nothing to the existing
  panes and can be defined freely. Rejected: a bottom dock beside Output (the
  earlier draft) — it would have to negotiate height with the Output panel and
  the editor on every project.

- **Decision: the window is a floating, always-available tool window — it does
  not block input to the IDE** (R36). Why: the feature *is* double-click to land
  in an editor behind it; a window that swallowed input would make its own main
  feature unreachable, and R35 keeps it open across exactly that jump. So
  "modal" here means *its own window*, not *input-blocking*. This is the one
  place the plan reads intent rather than words; if input-blocking really is
  wanted, R21's navigation has to change with it.

- **Decision: build the window on the proven `error_modal_scaffold` pattern, not
  a fresh `Resize`.** Why: "make it resizable" is a recorded, twice-burned
  failure in this codebase — egui ≥0.35 `Resize` does
  `desired_size = desired_size.max(measured_content_min)` **every frame**, so a
  body that overflows the box by even 2 px ratchets to full screen. The cure is
  already written and tested here:
  [`error_modal_scaffold`](crates/cobolt-ide/src/app.rs:667) seeds the size with
  `default_size` *only*, bounds it with `min_size`/`max_size`, then re-allocates
  `ui.available_size()` — the Resize box, never "remaining space of an
  auto-sizing parent". Rejected: rolling a new resizable container, and
  estimating the footer height (exactly what regressed in spec 027 when skrifa's
  font metrics made the real row taller than the estimate).

- **Decision: the interior is partitioned by embedded panels, with no estimated
  heights anywhere.** `egui::Panel::top` for the query field and options,
  `egui::Panel::bottom` for the Cancel/close row, `CentralPanel` for the
  scrolling result list — so measured content equals the box **exactly**,
  whatever the font metrics or however long the result list is. This is
  `error_modal_body_ui`'s shape and it is the reason R34 is achievable at all.

- **Decision: the result list scrolls inside the CentralPanel; the window never
  sizes itself to the results.** Why: R34. A 4000-hit query and a 0-hit query
  must leave the window exactly the same size. Rejected: `auto_shrink`/content
  sizing of any kind on the list.

- **Decision (spec Q2): menu action + toolbar button + shortcut.** Shortcut is
  `Ctrl`/`Cmd`+`Shift`+`F`, leaving `Ctrl`+`F` to the in-tab search (R28). The
  handler must match modifiers **exactly** — this repo has a recorded egui
  pitfall where `consume_key` ignores extra modifiers, so a loose match would
  make the in-tab search fire the project search.

- **Decision (spec Q5): single-click activates a diagnostic; double-click
  activates a search result.** Why: a log line is a link and single-click is the
  convention; the operator specified double-click for results, where a single
  click is selection. Both are stated in the spec's ACs so neither drifts.

- **Decision (spec Q3): the recycle bin stays excluded (R24) in this feature.**
  Why: simplicity first, and an opt-in toggle is additive later. Recorded as a
  follow-up rather than silently dropped.

- **Decision: `DiagMsg` gains a field rather than a parallel "rich diagnostic"
  type.** Why: seven construction sites and two consumers already speak
  `DiagMsg`; a second type would need converting at every boundary. The field is
  `Option`, so every existing producer is a one-line change and behaves as
  before.

- **Decision: search snapshots on the UI thread, scans on a worker.** Why: open
  forms live in `self.designers` and cannot cross a thread boundary; forms on
  disk need XML parsing that must not stall a frame. Snapshot the live ones,
  hand the worker the snapshot plus the paths to load, stream results back over
  a channel — the `Runner` pattern this codebase already uses. Rejected: scanning
  inline (blocks the frame on a big project) and holding a shared lock on the
  designers (invites a stall on the paint path).

## 5. Risks & mitigations

- **Risk: the byte-identical guarantee (R8) is broken by the threading
  refactor** — a stray `push_str` reordering while adding recording.
  → **Mitigation:** land the golden byte-comparison test (AC4) **first**, over
  the corpus, *before* touching any writer. A guard added afterwards proves
  nothing about the change it was supposed to guard.

- **Risk: off-by-N inside a site**, because the WORKING-STORAGE weaver skips
  leading blank lines and handler bodies are `trim_end()`ed.
  → **Mitigation:** `site_line_at_start` records the real offset; AC3 tests every
  site kind with **leading blank lines and trailing whitespace present**, not
  with tidy input.

- **Risk: an empty handler is blamed on the developer.** An unwritten handler
  emits a generated template stub, which `user_lines` deliberately excludes.
  → **Mitigation:** stub lines map to `Generated` (R12), with an explicit test
  that a diagnostic inside a stub is labelled generated code and attributed to no
  site.

- **Risk: two syntax validators disagree.** `validate_handler_syntax`
  ([designer.rs:1413](crates/cobolt-ide/src/panels/designer.rs:1413)) parses a
  handler *in isolation* with a 2-line scaffold and reports handler-relative
  lines; the Output path parses the *woven* program. The same code can produce
  different messages in the two places.
  → **Mitigation:** out of scope to unify here, but the plan names it: the woven
  check is authoritative, the modal keeps its fast local feedback, and reconciling
  them is a recorded follow-up. Do **not** quietly delete either.

- **Risk: search results go stale** between listing and jumping (the developer
  edits, then double-clicks an old hit).
  → **Mitigation:** R22 already forces live reads; additionally, a jump whose
  line no longer exists clamps to the end of the site rather than failing
  silently, and the panel marks the result set stale when a form it covered
  changed.

- **Risk: scope creep into a Problems panel.** The Output rows becoming
  interactive invites "while we're here, add a list".
  → **Mitigation:** §2 of the spec lists it as a non-goal; the plan touches
  `output.rs` only to render and activate.

- **Risk: the search window self-inflates** — the single most likely way this
  feature ships broken, because a long result list is exactly the overflowing
  body that triggers egui's per-frame `Resize` ratchet, and it will look fine in
  a screenshot of an empty search.
  → **Mitigation:** the scaffold + embedded-panel partition above (§4), plus
  AC17's **120-frame** size-hold test modelled on
  `error_modal_holds_seeded_size_across_frames`
  ([app.rs:17062](crates/cobolt-ide/src/app.rs:17062)) and run with a result list
  long enough to overflow. Write that test **before** the window has content.

- **Risk: the window closes itself** on a jump, on a click outside, or because a
  future refactor routes it through egui's popup manager — which force-closes any
  popup id not re-registered through `Popup::show` each frame (the recorded
  colour-picker regression).
  → **Mitigation:** open state is a plain `bool` on `CoboltApp` that only `✕`
  and Cancel clear (R35); the window never touches the popup manager. AC19
  asserts survival across a jump, an editor click and a re-Check.

- **Risk: "do not translate anything" is read too widely** and the new UI
  strings ship English-only, breaking the i18n completeness test and
  `tech.md`'s hard constraint.
  → **Mitigation:** §7 states the split explicitly — *documents* are English
  only; *IDE strings* stay `Tr` ×6.

## 6. Test strategy

**`cobolt-codegen` — `source_map_tests`**
- *Total attribution* (AC2): for a fixture form with code in all eight in-form
  site kinds, every generated line resolves to a site+line or to `Generated`;
  the test prints a table of `site → generated range → site lines` and the
  attributed/total line counts.
- *Per-kind accuracy* (AC3): a marker line placed at a known line of each site is
  found at exactly that site line after generation — run for all eight kinds,
  with leading blank lines present.
- *Byte-identical golden* (AC4, **written first**): `generate()` output for the
  corpus is unchanged; the test reports bytes compared and files checked.
- *Empty-handler stub*: a line inside a generated stub resolves to `Generated`.
- *Wrapper parity* (R29): `generate_with_user_lines` returns exactly today's
  ranges for the corpus.

**`cobolt-forms` — `code_site_tests`**
- *Round-trip* (AC1): every site kind → display path → resolve → the same site;
  prints the nine display paths so the format is reviewable by eye.
- *Enumeration completeness*: `code_sites()` yields one entry per non-empty site
  and the count matches a hand-written expectation for the fixture form.

**`cobolt-ide`**
- *Output rendering* (AC5): the rendered row text contains form, site path, line,
  column and the quoted source line — asserted on the produced text.
- *Activation* (AC6/AC7): activating a site diagnostic opens the owning editor
  with the caret on the mapped line and does **not** open the generated `.cbl`;
  a generated-line diagnostic offers no site jump.
- *Search correctness* (AC8): a query present in all nine site kinds returns nine
  results with correct paths and line numbers; the test prints the result table.
- *Options* (AC9), *live unsaved text* (AC10), *exclusions* (AC11),
  *jump into a closed form* (AC12), *empty state* (AC13).
- *Window holds its size* (AC17, **written before the window has content**): 120
  frames with an overflowing result list; size must not drift >0.5 px after it
  settles, and must settle near the seed — the direct copy of
  `error_modal_holds_seeded_size_across_frames`. The test prints the settled size
  and the max drift.
- *Grip resize sticks* (AC18): drive a drag on the grip, then re-query with a
  result list of very different length; the dragged size survives both.
- *Persistence* (AC19): the window is still open after a jump, after a click in
  the editor behind it, and after a re-Check; it closes on `✕` and Cancel and on
  nothing else.
- *Measured performance* (AC14): a generated project (forms × sites scaled to
  something defensible, e.g. 50 forms) reports forms scanned, sites scanned,
  occurrences, and elapsed ms — **numbers the run produced**, never asserted
  from a guess.
- *i18n* (AC15): the existing completeness test covers the new keys.
- *Non-regression* (AC16): in-tab search and the event double-click jump.

**Manual / visual**
1. `cargo run -p cobolt-ide`, open a project, put a syntax error in a control's
   `onClick`, in `WORKING-STORAGE`, and in `FILE-CONTROL`; run **Check**. Each
   Output row must name the form and site and quote the line; clicking each must
   open the right editor on the right line, and never the generated `.cbl`.
2. Open the search panel, query a data item used in several forms; confirm
   grouping, counts, highlight, and that double-click opens a form that was
   **not** already open in the RAD.
3. Type a new string into a handler without saving; re-run the search and confirm
   it is found.

## 7. Steering compliance

- [x] **i18n:** all new UI strings are `Tr` fields in six languages. Note: the
      site *display path* is COBOL identifiers and section keywords, which stay
      **English in every language** per the CRITICAL constraint — only the
      surrounding labels are translated.
- [x] **Generated-code banner + regenerate-on-action:** preserved. `write_header`
      untouched; the map is produced by the same call as the source (R9); output
      bytes unchanged (R8), guarded by AC4.
- [x] **English dev guide updated, translations untouched** — two new sections in
      `docs/developers-guide-en.md`. **Settled by the operator (2026-08-23):
      do not translate anything; keep the English version current.** That
      resolves the three-way steering contradiction in favour of `tech.md` /
      `structure.md`; the "Claude-maintained (GOLDEN RULE #8)" row in
      `specs/steering/docs.md` is now the wrong one and is corrected as a task in
      this change, so the next spec does not re-litigate it.
      **Why English-only:** the document structure changes once this
      implementation lands, so translating text that is about to be restructured
      is wasted work. A suspension with a reason, not a permanent reversal —
      expect translations to resume after the restructure.
      **Scope of that ruling:** it governs *documents*. The IDE's user-facing
      **strings** remain `Tr` fields in all six languages — a `tech.md` hard
      constraint, a `product.md` goal, and covered by an existing completeness
      test (operator, confirmed 2026-08-23). Nothing here ships an English-only
      UI literal.
- [x] **Fix vs feature:** **feature** → `feat/code-locations-and-search`, `z`
      bump, `CHANGELOG.md` entry, f=96 announcement when merged.
      ⚠️ If the operator classes the diagnostics half as a *fix* (errors pointing
      at an uneditable artifact is arguable as a defect), Rule #5 forbids one
      commit: `/tasks` then splits into layer 1+2 (`fix/`) landing first, and
      layer 3's search (`feat/`) second. The layering above is already cut so
      that split is a task-ordering change, not a redesign.
- [x] **No "cobolt" in user-facing text; COBOL identifiers English.** Site paths
      contain only form names, control ids, event names and COBOL section
      keywords.
- [x] **System KB:** no control/property/method/event changes, so the KB doc
      tables and `chunked.data` are untouched. `/tasks` re-checks if any task
      ends up changing documented behaviour.
