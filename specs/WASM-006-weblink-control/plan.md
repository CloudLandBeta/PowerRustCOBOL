# Plan — Hyperlink control (WASM-006)

- **Status:** draft, revised 2026-10-22 against the spec as it stands after the operator's answers of 2026-10-22 (Q1–Q6). Supersedes the plan of 2026-10-20, which covered the player half only.
- **Spec:** ./spec.md   **Date:** 2026-10-22
- **Branch:** `features-2x` (2.x.x). Feature. `README.md` and `docs/` are not touched; what 2.x.x says about the control lives in specs/ and in the System KB.

## 0. What changed since the plan of 2026-10-20, and why

| # | Change | Why |
|---|---|---|
| C1 | The control is **`Hyperlink`**, a real `ControlType` variant, not a `ControlType::Custom` named `WebLink` that only the player recognises | Q1 decided (operator, 2026-10-22): named Hyperlink; R1 asks for a control type of its own in every toolbox |
| C2 | The control exists on **desktop** too: a click opens the system browser in all three desktop hosts | Q1 decided; R16, AC10 are new. The old plan's "web and mobile only" scope is gone |
| C3 | The link policy (`normalize`, `check`, `plan`) moves from `cobolt-web-player/src/weblink.rs` to **`cobolt-forms`**, so the player, the desktop host, the interpreter's `SetUrl` and the Designer's Properties panel use one function | R7 now applies in the designer (AC4) and on desktop (R16); two copies of a security check drift |
| C4 | **Cancel is now planned, not declared out of reach.** A click on a link that has a handler bound to `onClick` or `onBeforeNavigate` is default-prevented and navigated from script after the handler; a link nobody handles stays fully native | Q3 decided: a property. The old plan's decision "never `preventDefault`" left R6/R13/AC6 unmet; the clean design it named is now the decision |
| C5 | The modifier-key table is **per operating system**: Apple platforms follow Safari, Linux and Windows follow Chrome | Q2 decided (operator, 2026-10-22). The old `plan()` applied one table everywhere (Shift = new window, which is not Safari's meaning) |
| C6 | Addresses go **through the platform's URL parser** (the browser's `URL`, the WHATWG `url` crate natively); the parsed form is what is stored, shown and checked | Q6 decided |
| C7 | The `:visited` subset is **declared**: `VisitedColor` (text colour) only | Q5 decided: declare the supported subset |
| C8 | A link to another form of the same application goes **through the router** (WASM-011) | Q4 decided: the router |
| C9 | **Gap found in the code, recorded honestly:** `Open` and `OpenIn` (R12) queue page commands `open` / `open-in` (`weblink.rs::method`) but `dom/instance.rs::run_command` has no arm for them and drops them (`_ => {}`). The old plan and tasks.md T4 called them done; they are not | Read on 2026-10-22; the old status line was wrong on this point |
| C10 | The spec's §1 claim "nothing opens a URL" is incomplete: the desktop **already hands a document to the OS opener** (`cobolt-form-host/src/os_handoff.rs::command_for`, `Handoff::Share` → `open` / `xdg-open` / `cmd /C start`) through a request/answer property pair (`host.rs::viewer_os_request`, `drive_viewer_os_handoffs`). R16 reuses that path; it does not reuse `cmd /C start` for a URL (§4 D7) | Grounding |

Kept from the old plan because it is still right: the anchor rendering, `noopener noreferrer` by default (R8), no `ping` (R3, D14), "refuse, never rewrite", the policy as pure functions tested without a browser, the project's extra schemes that can never widen the dangerous list, and the seven existing `weblink` unit tests (moved with the code, renamed).

## 1. Approach

One model type, one policy, three renderers (Designer painter, desktop run-form, web player), with the navigation itself done by whatever the platform owns.

- **R1 — the type.** `ControlType::Hyperlink` in `cobolt-forms/src/model.rs`, in `ALL`, with `as_str`/`from_str` `"Hyperlink"` (and `from_str("WebLink")` read as `Hyperlink`, so a 2.x.x fixture or hand-written `.cfrm` written with the player's interim name loads; it is always saved as `Hyperlink`). It inherits the Label's seeds, events and methods by sharing the Label's arms (`default_size` (120, 20) as the Label's, `supported_events` = the Label's list plus `onBeforeNavigate` and `onNavigated`, `primary_event` `onClick`, not non-visual, `has_perspective` as the Label's). Available in the toolbox of every project kind.
- **R2 — look.** Caption painted as link text in `LinkColor` (default: the form theme's hyperlink colour), `Underline` = `Always` (default) | `Hover` | `Never`; `Control::new` seeds `Cursor` = `Hand` (the existing universal property, so the developer can still pick another). On the web the existing `pr-weblink` CSS rules become `pr-hyperlink` (`base_css.rs`), state colours through `--pr-link`, `--pr-hover`, `--pr-active`, `--pr-visited`.
- **R3 — properties** (the names the player already reads, now seeded by the model): `Url`, `Target` (`Self` | `NewTab` | `NewWindow` | `Parent` | `Top`), `WindowFeatures`, `Rel`, `Download`, `HrefLang`, `MimeType`, `ReferrerPolicy` (the eight HTML values), `Underline`, `AccessibleLabel`, `LinkColor`, `HoverColor`, `ActiveColor`, `VisitedColor`, and the run-time flag `Cancel`. **No `ping`** (operator, 2026-10-20). `HrefLang` and `MimeType` are written to `hreflang` / `type` on the anchor (the current `view/controls.rs::weblink` does not write them yet — a gap this plan closes).
- **R4 — accessible name** = Caption, overridden by `AccessibleLabel` (`aria-label`); `Tooltip` → `title`. Desktop: the painter's accesskit node carries the same name.
- **R5 — click.** Order on every platform: `onClick` (argument: the modifier text, ABI §12.2) → `onBeforeNavigate` (argument: the planned `target⇥url`) → navigation → `onNavigated` where it can run (below). Modifier keys are read from the event and mapped by the **per-OS table** (D3).
- **R6, R13 — Cancel.** `Cancel` is reset to false before `onClick`; after the handlers return, a true `Cancel` stops the navigation. On the web this needs the default prevented **only when one of the two events has a bound handler** (the manifest's handler list, `tree.rs::Ctl::has_handler`); otherwise the anchor stays native and the browser does everything (D1). `onNavigated` is raised only where the application is still loaded afterwards: a fragment link (R10), a same-app route handed to the router (Q4), and a new tab/window. A navigation that unloads the page cannot raise it — **interpretation to confirm** (§7 OQ1).
- **R7 — what it accepts.** `cobolt_forms::hyperlink::check(url, allow_data, &Policy)` (moved from the player): `http`, `https`, `mailto` (with `subject`, `body`, `cc`, `bcc`), `tel`, `sms`, relative, fragment, plus the project's extra schemes; `javascript:`, `vbscript:` always refused however spelled; `data:` only for a `Download`. Applied at the four writers: the Properties panel, `.cfrm` load (a refused stored value is kept as written — user data is sacred — but the control is inert and the Designer shows the refusal), `SetUrl` (interpreter and player), and every click.
- **Q6 — the parser.** Before `check`, the address is parsed by the platform's URL parser relative to the base: the browser's `URL` (`web_sys::Url::new_with_base` against `document.baseURI`) in the player; the WHATWG `url` crate natively (Designer, desktop host, interpreter). Percent-encoding and IDN display are the parser's; the Properties panel shows the parsed form under the field. The stored `Url` is what the developer typed; the parsed form is what is checked and followed.
- **R8 — `rel`.** Empty `Rel` on a new context → `noopener noreferrer`; an explicit `Rel` is written as set. A script-opened context (D1) passes `noopener,noreferrer` in the features unless `Rel` loosens it.
- **R9 — keyboard and focus.** A real `<a href>` is focusable and Enter-activated natively; the focus ring comes from the player's `:focus-visible` rule. On desktop the control takes the tab order like a Label does (`takes_tab_order`), Enter activates, the painter draws the focus ring. The browser's context menu (open in new tab, copy link address) stays; those choices raise no event (the browser gives the page none).
- **R10 — fragment links.** `#name` resolves to a control of the form by name (case-insensitive) or to an element id; the player scrolls it into view and focuses it (a page command `scroll-to`, run in `dom/instance.rs::run_command`). On desktop the same resolution scrolls the form's scroll area and sets focus.
- **R11 — mobile shell.** In the Tauri shell (WASM-012) an address outside the application's origin and every `mailto:`/`tel:`/`sms:` go to the system through the shell's opener; the player detects the shell from the host page's configuration. Lands with WASM-012; the player side is the routing switch only.
- **R12 — methods.** `SetUrl`, `GetUrl`, `Open`, `OpenIn(target)`, `SetCaption`, `GetCaption`. `SETURL`, `GETURL`, `OPENIN` are added to `cobolt-ast/src/methods.rs::is_known_method` (`OPEN` is already there); implemented by the interpreter (desktop) and by the player's `methods.rs` dispatch (web — the generated module issues them as ABI `CALL` commands). The player's `open` / `open-in` page commands get their missing arms (C9). A method-driven `Open` has no user gesture: a new-tab/new-window open from it can be blocked by the browser, reported with the existing pop-up notice (`dom/ops.rs::open_window`).
- **R14 — Designer.** The painter (`paint.rs`) draws the link face; in-place Caption edit as the Label's; the Properties panel gets the enum editors (`Target`, `Underline`, `ReferrerPolicy`) and the `Url` field with live `check` + parsed form + refusal indication; the click is tried in the Preview (WASM-008).
- **R15 — catalogue.** `tests/controls/` test, `ControlType::ALL` tests, KB tables, `chunked.data`, toolbox icon, six languages.
- **R16 — desktop.** Any `Target` → the system's default browser; `mailto:`/`tel:`/`sms:` → the OS handler. Path (reusing spec 058's handoff): render outcome → if a handler is bound, the runtime runs `onClick`/`onBeforeNavigate`, reads `Cancel`, and writes the request property `_NavigateRequest` (value: the parsed URL); otherwise the form host takes the request straight from the render outcome. `host.rs::viewer_os_request` gains the `_NavigateRequest` / `_NavigateAnswer` pair, `os_handoff.rs` a `Handoff::OpenUrl` whose opener takes the URL as **one argument, never through a shell** (D7). Because `cobolt-form-host` is the one host of `rcrun run-form`, embedded child forms and the compiled binary (`cobolt-cli/src/form_gui.rs`, `cobolt-compiler`), one change reaches all three.

## 3. Data / model changes

- `.cfrm`: a new `type="Hyperlink"`; its properties are ordinary `<Property>` entries. Additive; 1.x.x never reads a 2.x.x form. `type="WebLink"` is read as Hyperlink and written back as Hyperlink.
- **Project setting:** the extra link schemes. No project-file source exists today — `BundleOptions::weblink_schemes` is filled only by tests and `examples/fixture_bundle.rs`. Proposal: an additive `cobolt.toml` key (`[links] schemes = [...]`, empty by default) read by the web Build (WASM-002's wiring) and by the desktop host. The exact carrier into `rcrun run-form` is decided at `/tasks` after reading how run-form receives project settings — not guessed here.
- ABI: **amendment A10** to `WASM-ABI-v1.md` in the implementing commit: `onBeforeNavigate` (argument `target⇥url`) and `onNavigated` (argument `url`) rows in §12.2; the §12.1 `Navigate`/`OpenUrl` row should cite **R7** (it cites R4, the accessible-name requirement). The generator is affected only through the `events` name table.
- No AST or serialization change; `is_known_method` grows three names.

## 4. Key decisions & alternatives

- **D1 — Native unless intercepted.** A link with no handler bound to `onClick` or `onBeforeNavigate` is a plain anchor; the browser navigates. A link with one is default-prevented; after the handlers (and `Cancel`) the player navigates from script (`location.assign` for `Self`/`Parent`/`Top`, `window.open` for new contexts, an anchor `click()` for a download). — Why: R5 and R6 together; only a link someone intercepts pays the price. — Rejected: never preventing (Cancel impossible, the old plan's position); always preventing (every link loses native conventions).
- **D2 — Cancel is read after both events.** Reset before `onClick`, honoured if set in either handler. — Why: R6 names the click event, R13 the before-navigate event. — Rejected: only in `onBeforeNavigate` (contradicts R6's wording).
- **D3 — The modifier table follows the OS (Q2).** Detected from `navigator.userAgentData.platform` / `navigator.platform` in the player, `std::env::consts::OS` natively. *Chrome (Linux, Windows):* Ctrl-click and middle-click → new tab; Shift-click → new window; Alt-click → download. *Safari (macOS, iOS, iPadOS)* — **verified 2026-10-23** against Apple's *Safari User Guide › Keyboard and other shortcuts* (support.apple.com/guide/safari/cpsh003, macOS 27, © 2026; the page carries no date of its own): ⌘-click → new tab (in the background); ⇧⌘-click → new tab, made active; ⌥-click → download the linked file; Shift-click → Safari's "add to Reading List", which a page cannot do → a plain click. **Corrected:** the ⌘⌥-click → new window row written from memory is **not on Apple's page** and is dropped; ⌘⌥-click is read as ⌘-click (new tab). Middle-click is not on the page either; it keeps Chrome's row (new tab) as a working assumption, measured in the headless run (T18) like the `auxclick` risk in §5. The table applies only on D1's scripted path and to the desktop's event argument; a native anchor uses the browser's own table.
- **D4 — One policy in `cobolt-forms`.** — Why: four writers, three hosts, one security rule. — Rejected: keeping it in the player and copying a desktop version.
- **D5 — Refuse, never rewrite** (kept). A refused address leaves the control inert and says why; a refused value read from a `.cfrm` is kept as written and flagged.
- **D6 — `onNavigated` only where the application survives the navigation** (see OQ1).
- **D7 — The desktop opener never goes through a shell.** `os_handoff.rs::command_for` uses `cmd /C start ""` on Windows for Share; `cmd` re-parses `&`, `|`, `^` in its arguments, and a URL's query string contains `&`. The URL opener on Windows calls a program that takes the URL as a single argument (`rundll32 url.dll,FileProtocolHandler` is the candidate — to be confirmed on Windows at `/implement`), `open` on macOS, `xdg-open` on Linux, on a thread as `hand_off_async` does. — Rejected: a new crate dependency (`open`, `webbrowser`) while the handoff module already exists.
- **D8 — `:visited` subset (Q5):** `VisitedColor` is the text colour; browsers apply only colour properties to `:visited` and ignore their alpha. Desktop has no history and ignores it.
- **D10 — `LinkUnderline`, not `Underline` (found at `/implement`, 2026-10-30).** Every control already has a Boolean `Underline` — the font's (`model.rs` `Control::new` universal seeds), read as a font flag by `paint.rs` (`FontStyle`, `paint_styled_galley`) and the Properties panel's font row. A String `Always|Hover|Never` under the same name would collide with it, so the link's three-state rule is the property `LinkUnderline`; the font's `Underline` keeps its meaning on a Hyperlink too.
- **D11 — Desktop sequence and the project policy (found at `/implement`, 2026-10-30).** The interpreter cannot see `cobolt-form-host`, so the published `[links] schemes` live in `cobolt_forms::hyperlink` (`publish_project_schemes` / `project_policy`), and `cobolt_form_host::seeding::publish_link_schemes` delegates to it. On desktop the click sequence is advanced at each `COBOL-WAIT-EVENT` (the handler before has returned), as the player's host queues `Work::Link` behind the handler; the desktop's `onBeforeNavigate` carries no argument (the desktop queue carries none — a handler reads `LNK-1::Url` and `LNK-1::Target`), and the click's modifier text travels on the render outcome and the `onClick` `FormEvent` value. A link is intercepted (scripted) when `onClick`, `onBeforeNavigate` **or `onNavigated`** is bound — `onNavigated` added so OQ1's "raised for new contexts" can hold on the scripted path.
- **D9 — The URL parser (Q6):** `url` is already in `Cargo.lock` (transitively); it becomes a workspace dependency used by `cobolt-forms`. — Rejected: the hand-written `normalize` alone (it models the scheme scan, not percent-encoding or IDN).

## 5. Risks & mitigations

- **Pop-up blocking on the scripted path.** `window.open` needs transient user activation; a handler that suspends (a `Confirm` dialog, a remote `CALL`) outlives it. → Same-context navigations are unaffected; a blocked new context reports the existing pop-up notice (`dom/ops.rs::open_window`) and raises nothing else; KB usage note says "do not wait in a link's handler before a new tab".
- **`Cancel` collides with a method name.** `CANCEL` is in `is_known_method` (`methods.rs:152`), and an inline `Ctrl::Name` resolves against that list. → Parser tests: `SET LNK-1::Cancel TO TRUE` and `IF LNK-1::Cancel` read the property; fixed in the parser if not.
- **Middle-click prevention.** `auxclick` `preventDefault` stops the new tab in Chrome; Safari's behaviour is to be measured. → The headless run of AC2 covers both engines; a failure is recorded, not hidden.
- **Desktop opener differences.** `xdg-open` may be absent. → The refusal reason is reported through `LastError` exactly as the Share path does (`drive_viewer_os_handoffs`).
- **A script built from data.** → `check` on every write and every click; tests for the dangerous schemes however spelled (kept).
- **Renaming interim names** (`WebLink`, `pr-weblink`, `weblink_schemes`). → Read aliases for the `.cfrm` type and the config key; the class rename is internal to the player.

## 6. Test strategy

Each test prints what it measured.

- `cobolt-forms` (`hyperlink` module): the seven moved tests (dangerous schemes however spelled; project widening but never for them; target and `noopener noreferrer`; modifiers; download/features/referrer policy; empty and refused addresses), plus: the per-OS table for macOS/Linux/Windows; parsing (percent-encoding, an IDN host, a relative address against a base); `from_str("WebLink")` = Hyperlink and saved as `Hyperlink`; `.cfrm` round trip with every property at a distinct value (AC7); `Control::new` seeds `Cursor = Hand`.
- `cobolt-ast`: `SETURL`, `GETURL`, `OPENIN` are methods; the `Cancel` property parses as a property (both risk cases above).
- `cobolt-runtime`: `SetUrl("javascript:…")` refused, control unchanged, refusal reported (AC4); `Cancel` set in `onClick` / in `onBeforeNavigate` → no `_NavigateRequest`; not set → one (AC6).
- `cobolt-form-host`: `command_for(OpenUrl, os)` for the three OSes, the URL passed as one argument with `&` intact; a request with a refused scheme never reaches the opener (AC10).
- `cobolt-web-player`: `kinds` 63 rows; the bound-handler branch prevents the default and the unbound one does not; `open`, `open-in`, `scroll-to` have arms (C9 regression); the anchor carries `hreflang`, `type`, `aria-label`, no `ping`.
- `cobolt-compiler`: KB freshness test `prebuilt_chunked_kb_matches_the_published_documentation` green after regeneration (AC7).
- The `ControlType::ALL`-driven suites across crates (`--no-fail-fast`, `cobolt-forms --features render`, `cobolt-ide --bin`), every `test result` line read.
- **Headless browser** (WASM-015's harness, gallery bundle): AC1 (text, computed `cursor: pointer`), AC2 (each `Target`, modifiers, the click argument), AC3 (`window.opener` null with empty `Rel`), AC5 (`mailto:` with subject/body, `tel:`, relative, fragment, `Download`), AC6, AC8 (Tab, Enter, focus ring, an automated accessibility check — the tool is WASM-015's choice, run from outside the tree under the PRIME DIRECTIVE). The Chrome 152 run recorded in the old plan (anchor, `rel`, no `ping`, `javascript:` refused by `SetUrl`, `mailto:` accepted, plain click not prevented) is evidence for the old code; it is re-run after the move, not carried forward.
- **Desktop, by the operator** (memory: the agent never drives the application window): a Hyperlink on a form opens the browser under `rcrun run-form`, in an embedded child form and in a compiled binary (AC10); the Designer face and the Properties panel's refusal indication, in six languages.
- **Mobile** (AC9): on a device or simulator once WASM-012's shell exists; listed as not run until then.
