# Plan — The prebuilt player (WASM-016)

- **Status:** draft, revised 2026-10-22 against the spec as it stands after the operator's answers of 2026-10-22 (2.0.29). Supersedes the plan of 2026-10-20, which described the player as built; §0 says what changed and why.
- **Spec:** ./spec.md   **Date:** 2026-10-22
- **Companions:** `specs/WASM-INDEX.md` (D10, D14–D17, D20), `specs/WASM-PLAN.md` (W4), `specs/WASM-ABI-v1.md` (§11 host checklist, A5–A9).

The tools measured in the plan of 2026-10-20 were: rustc 1.95.0 (stable, MSRV 1.92), `nightly-2026-10-08` for the threaded variant,
`wasm-bindgen` 0.2.129 (crate and CLI), `wasm-opt` 133, node v23.3.0, Chrome 152. The numbers quoted from that run are kept as a
**baseline** to compare against, not as the shipped state after this plan.

## 1. Approach

### 1.1 The pure core stays (R5, R7–R10, R13b)

`crates/cobolt-web-player` keeps its two halves. **The pure core** — `src/host.rs` (the ABI v1 host: commands, queries, tasks and
suspension per ABI A5, remote calls, error frames A6, verbs A7), `src/tree.rs` (the form tree), `src/methods.rs`, `src/view/*`
(turns a tree and the page-only state into plain `VNode` data), `src/net.rs` and `src/auth.rs` (sans-IO machines: WebSocket
framing A8, back-off, token refresh, origin allow-list) — is tested natively with no browser and is not touched by C1. R7
(deliver events, carry out commands), R8 (perform waits, queue events in order per instance), R9 (the connection) and R10
(routing, `super::` in `src/superlink.rs`) are met here, as before.

### 1.2 The browser half moves to Leptos (R1, C1)

Today the browser half is `src/api.rs` (the `#[wasm_bindgen]` `Player`, 1,160 lines) and `src/dom/*` (≈3,470 lines: `apply.rs`
patches the real DOM from `VNode`s, `instance.rs`, `ops.rs`, `find.rs`, `canvas.rs`, `captcha.rs`, `sheets.rs`), joined to the core
by the `pub(crate) trait Surface` (`src/api.rs:285`: `opened`, `closed`, `render`, `effect`, `net_state`, `styles_changed`,
`unmount`, `ui_op`, `act`).

The Leptos implementation is a new implementor of that same trait, in client-side-rendering mode, mounted on the element the loader hands
over (the mount call is the chosen release's; not checked in this session, see §5):

- **State as signals.** One reactive store per form instance: the instance's `VNode` tree, its page-only state (open menu, grid
  window and sort, find total, focused control) and its **layer `Visible` set** (R19). `Surface::render` writes the signals;
  Leptos updates only the nodes that changed. `dom/apply.rs`'s hand-written diff is retired.
- **One generic component renders a `VNode`.** The views stay data (`src/view/*` unchanged), so the native tests keep asserting on
  them; the component maps a `VNode` element, its attributes and children to Leptos elements and its listeners to `on:` handlers
  that build the existing `Payload` (`dom/payload.rs`) and call `view::interact::on_event`. This keeps R5's "each control once":
  a control is one view function, drawn by one component.
- **What Leptos does not model stays `web-sys`,** reached through a `NodeRef` in an effect: canvas contexts (`dom/canvas.rs`), the
  Find ranges (`dom/find.rs`), the captcha frame (`dom/captcha.rs`), constructable stylesheets (`dom/sheets.rs`), the Rayon pool.
- **No markup strings (R15).** Leptos's `inner_html` attribute joins the forbidden names of `tests/sinks.rs` (`FORBIDDEN` already
  holds `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `set_inner_html`); the Viewer keeps building nodes from its allow-listed
  parsed tree (`src/view/svg.rs`, `src/view/viewer.rs`).
- **Disposal (R13b).** `unmount()` disposes the Leptos owner of the mount (which drops every signal and effect) and then the few
  `wasm-bindgen` objects already listed; panics keep `panic = "abort"` and the readable-error path (`force_panic_for_test`,
  `src/api.rs:1143`).
- **Order of work.** The Leptos `Surface` is built beside `dom/`, both behind one cargo feature for the duration of the change;
  the node end-to-end scenarios of `cobolt-web-bundle` run against both; `dom/` is removed in the same series once they agree, so
  no second DOM layer survives the change.

**Build tool (working assumption, to confirm).** WASM-017 R17 names `cargo-leptos` with the pinned `wasm-bindgen` CLI and
`wasm-opt`; WASM-002 Q2 and WASM-003 R2 apply `cargo-leptos` to the **server** that runs the developer's COBOL. The player is a
client-only library with two variants and three parts, which `examples/build_player.rs` already drives with `cargo` + the pinned
`wasm-bindgen` CLI + `wasm-opt`. Working assumption: the player keeps that path (the same tools R17 lists, Leptos as a library) and
`cargo-leptos` is used where there is a server (WASM-003). If the operator means `cargo-leptos` to drive the player build too,
`build_player` calls it instead and the freshness record names it; nothing else in this plan changes. **Open — Q-P1, §8.**

### 1.3 The form description: versioned JSON (R3, R4, Q1)

A new module **`cobolt_forms::description`** (model-only: it builds with `default-features = false`, which the player already
uses — `crates/cobolt-web-player/Cargo.toml:55`) defines the schema and the two conversions:

- `describe(&Form) -> FormDescription` — called after `load_form_from_str` (`crates/cobolt-forms/src/xml.rs:595`), so the `.cfrm`
  migrations and `seed_missing_props` run **once, at Build**, by the one parser. It copies what the player draws and **omits by
  construction** what R4 forbids: handler code, `user_ws_source`, `cobol_structure`, `user_procedures`, `deleted_code` (the fields
  `cobolt_web_bundle::form_description` clears today, `crates/cobolt-web-bundle/src/lib.rs:322-343`). Omitting at the type level
  replaces clearing: a new code-bearing field of `Form` cannot leak, because the description has no place for it.
- `to_form(&FormDescription) -> Result<Form, DescriptionError>` — the player rebuilds the same `cobolt_forms::model::Form` its
  tree is made from (`src/tree.rs`), so the player's typed model is still the desktop's and no property is re-typed by hand.
- `DESCRIPTION_FORMAT: u32` lives here; `cobolt_web_bundle::DESCRIPTION_VERSION` (`lib.rs:47`) and the hard-coded `"description": 1`
  in `versions()` (`src/api.rs:1152`) both read it.

The player's `Player::add_form(xml)` (`src/api.rs:821`) becomes `add_form(json)`; it refuses a description whose `format` it does not
read with a message naming both numbers. The Build (`cobolt-web-bundle`) and the Preview (`crates/cobolt-web-preview`, WASM-008)
call the same `describe`, so R3's "the same description feeds the Preview and the Build" is one function. The secret scan
(`crates/cobolt-web-bundle/src/secrets.rs`) runs over the JSON as it ran over the XML.

### 1.4 Versions and pinning (R11, R12, Q6)

- **The triple.** `versions()` answers `{abi, description, player}` from `cobolt_wasm_abi::ABI_VERSION`, `DESCRIPTION_FORMAT` and
  the crate version; `player-build.json` records the same triple, so a player on disk is identified without running it.
- **Default:** the Build copies the **current** player, the one built from this source and recorded in
  `assets/web-player/player-build.json`.
- **Pin:** the project's Web (or Mobile) settings gain `player = "<version>"` — a field of `WebSettings` / the mobile settings in
  `cobolt_compiler::project_kind`, read through `WebBuildRequest::from_manifest` (`crates/cobolt-project-tools/src/web/mod.rs:71`).
  Absent = current. The Build then: (1) finds that player in the archive; (2) reads its triple; (3) asks the generator to emit for
  that `abi` and the description writer for that `format`; (4) if either is not in the compiler's supported set, **fails** with a
  message that names the pinned version and the oldest it can still emit. The module's own import check (ABI §3, AC6) stays as the
  last line.
- **The archive.** Released players are kept under `assets/web-player/archive/<version>/` with their `player-build.json`; the
  current player stays at `assets/web-player/{plain,threaded,parts}`. The IDE resolves the directory beside the executable, as
  `images_dir()` and `CoboltApp::themes_dir()` do (`crates/cobolt-ide/src/app.rs`, test `bundled_directories_resolve_beside_the_executable`),
  never from `CARGO_MANIFEST_DIR`; the installers copy it. Which old versions are kept is **open — Q-P2, §8**.
- **No toolchain at the developer's machine (R1):** pinning only selects files; nothing is compiled.

### 1.5 What reaches the browser of the form host's behaviour (R6, R14, Q4)

Carried, as specs 037/038/042 define them: the window properties that have a page meaning (title, background and backdrop, size
as the content box), the lifecycle events of spec 037 in the desktop order, event dispatch to bound handlers only (ABI §7), timer
and animation pacing. **Not carried (operator, 2026-10-22):** entrance and exit effects (spec 038), window states (minimise,
maximise, full screen as a window state) and window positions. A verb that asks for one of them (`me::SetFullscreen`, a position
property) is accepted and does nothing, and the R14 harness lists it as an expected difference instead of a failure. The list is
kept in one table, `specs/WASM-016-prebuilt-player/differences.md`, written by the implementation (this plan writes no other file).

### 1.6 Form layers (R18, R19; WASM-004 R13–R24; ABI A9)

The description carries `layers` in stack order (name and backdrop, never `Visible` — the model's `Layer` has none either,
`crates/cobolt-forms/src/model.rs:8316`) and each control's `layer` (absent = `Form`); a form with no layers carries an empty list
that is not serialised. The player keeps a `Visible` set per **instance**, empty (all hidden) when `pr_open_form` creates it,
applies `SET` on a layer id (ids `3 + n …` per A9) on the next frame, and drops it with the instance. A layer is a stacking context;
a hidden layer is `inert` (D20). The manifest side of A9 (`forms[i].layers`) is the generator's (`cobolt-wasm-abi`'s `FormEntry`
has no `layers` field today, `crates/cobolt-wasm-abi/src/manifest.rs:67`) and is a dependency, not this plan's change.

### 1.7 Size and parts (R13, Q3)

Parts on first use stay as built: Mermaid, the PDF reader, the Canvas 2D rasteriser (`parts/{mermaid,pdf,canvas}`), loaded through
the loader's integrity-checked `part` / `partModule`. Charts, maps and the Viewer are added as parts where they can be split out
without a second copy of the core; WASM-018's Canvas 3D and graphics objects are parts by R13. The Build report
(`cobolt_project_tools::web::BuildReport`, `PartSize`) states the player's size and each part's.

## 3. Data / model changes

- **The form description (new public format).** JSON, one file per form:
  `{ "format": 1, "name", "kind": "web"|"mobile", "form": {window properties…}, "layers": [{name, backdrop}], "controls":
  [{name, type, parent, layer, properties: {name: PropValue}, events: [event names bound]}], "data_bindings": […],
  "breakpoints": […], "stylesheet": "<bundle path>" }`. `PropValue` already derives `Serialize`/`Deserialize`
  (`crates/cobolt-forms/src/model.rs:52`); `Form`, `Control`, `Layer` and `EventBinding` do not, so the schema is its own set of
  types — which is also what lets `format` change on purpose and only on purpose. Fields are added compatibly
  (`#[serde(default)]`); a removal or a meaning change bumps `format`.
- **`.cfrm` / `.wcfrm` / `.mcfrm`:** unchanged.
- **`cobolt.toml`:** an optional `player` key in the Web and Mobile tables; old manifests read as before.
- **`player-build.json`:** gains the version triple; keeps `source_hash`, the tools, the nightly and the `files` list.
- **Page-only state** (never written back): as before, plus the per-instance layer `Visible` set.

## 4. Key decisions & alternatives

- **Leptos as the browser half, the core unchanged (C1).** Why: the spec and the answers of 2026-10-22 require it; keeping
  `VNode` data between the core and Leptos keeps the native test suite that the plain `web-sys` version was built for.
  Rejected: (a) keeping plain `web-sys` — contradicts R1 as it stands; (b) rewriting the views as Leptos components with state in
  signals throughout — loses the native assertions on views and couples every control to the framework.
- **The description is its own schema in `cobolt-forms` (C2).** Why: versioned on purpose (R11), code-free by construction (R4),
  one parser of `.cfrm` at Build. Rejected: deriving `serde` on the whole `Form` model (the format would follow every internal
  rename and could carry code fields); the sanitised XML (superseded by Q1).
- **`opt-level = "s"` (C5).** The operator's ruling. Its measured cost on the 2026-10-20 source was +581,902 bytes before
  `wasm-opt` (2,718,057 against 2,136,155); the Build report shows the real figure after the change.
- **A separate Cargo workspace — kept.** `wasm-bindgen` must equal the CLI exactly (`=0.2.129`, `Cargo.toml:75`) while the main
  lock pins another; the browser closure (now with Leptos) stays out of the main lock; nightly and `-Zbuild-std` stay in this build.
- **Parts on demand — kept (Q3).** Baseline 2026-10-20: plain player 2,222,253 bytes (gzip 772,899); Mermaid 1,906,933, Canvas 2D
  469,419, PDF 219,273, none fetched by a form without them.
- **Patched vendored crates — kept:** `vendor/mermaid-rs-renderer` (a clock on `wasm32`) and `vendor/time` (no `stdweb`), each to be
  dropped when upstream removes the need.
- **Rayon's pool cannot be disposed — kept as a stated limit of R13b.** `wasm-bindgen-rayon` has no stop; `unmount()` releases
  everything else. Pool size `hardwareConcurrency − 1`, capped at 8 (WASM-017 Q2), as the loader already computes.
- **Plug-ins (Q5).** Loaded modules, through the part loader's integrity-checked fetch; nothing in v1 implements them.

## 5. Risks & mitigations

- **Leptos's MSRV, size and `wasm-bindgen` requirement.** No Leptos release was checked in this session (none is in the local
  registry). → At `/tasks`: choose the newest release whose MSRV is ≤ 1.92 and which accepts `wasm-bindgen = 0.2.129` (or move the
  pinned CLI with it); the dependency guard and the licence check gate it; if none qualifies, stop and report to the operator
  rather than pin a nightly for the plain variant.
- **Size growth from Leptos plus `"s"`.** → Measured by `build_player --measure` against the baseline above and reported; parts
  absorb heavy controls.
- **The Leptos switch regresses behaviour already proved.** → Both surfaces behind one feature until the node end-to-end scenarios
  and the Chrome checks pass on the Leptos one; then `dom/` is removed.
- **Drift from the desktop host (spec 042).** → R14 harness (§6) with the expected differences of §1.5 as data.
- **A pinned player outlives the compiler's ability to emit for it.** → Build error naming the version (R11); never a run-time surprise.
- **Repository growth** (every archived player is ~7 MB of variants and parts). → Bounded by Q-P2.
- **Stale shipped player.** → `tests/freshness.rs` (AC7).

## 6. Test strategy

Native: `cargo test --manifest-path crates/cobolt-web-player/Cargo.toml` (lib, `abi_host`, `sinks`, `dependency_guard`, `freshness`);
`cargo test -p cobolt-forms` (description); `cargo test -p cobolt-web-bundle` (assembler, CSP, node end-to-end). Each test prints what it
checked (counts, sizes, names).

| AC2 | `cobolt-forms` `description` round trip over every example form; player view tests over a one-of-each class A/B form | `to_form(describe(f))` equals the code-free form; every control drawn; the WASM-004 R11 property round trip |

## 7. Steering compliance

- [x] i18n: the player's own fixed texts are the host page's (WASM-002 R15); the Build report and the pin error are IDE `Tr` keys in six languages.
- [x] Generated-code contract: descriptions, the host page, the loader and the stylesheet are generated at every Build with the banner where the format allows one; the player is a built artefact with a freshness test.
- [x] PRIME DIRECTIVE: no hand-written JavaScript remains in the tree once WASM-002's generator lands (C7); the wasm-bindgen glue under `assets/web-player/` is built output, like `chunked.data`.
- [x] Interpreter/binary parity: the player hosts no interpreter; parity with the desktop form host is R14's harness.
- [x] System KB: the description format and the `player` pin are documented in the compiler's KB tables and `assets/knowledge/chunked.data` is regenerated in the same change.
- [x] User code is sacred: a description never alters the form file; a pin is only ever written by the developer.
- [x] `README.md` and `docs/` untouched (2.x.x).
- [x] Fix vs feature: feature, on `features-2x`; `z` and the CHANGELOG at the coordinator's merge.
- [x] Leptos (R1): adopted (C1).
