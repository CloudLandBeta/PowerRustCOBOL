# WASM parity ledger — where a generated module and the interpreter differ

Every difference between the WebAssembly line (2.x.x) and the interpreter (1.x.x), with who is right. A difference that is the **interpreter's** defect is a fix for `main` (GOLDEN RULE #5) and is forward-ported; it is listed here until the operator decides. A difference that is deliberate stays here as the record of why.

| # | Construct | Module | Interpreter | Who is right | Status |
|---|---|---|---|---|---|
| 1 | `IF N = ZERO` where `N` is a numeric item with `BLANK WHEN ZERO` holding zero | true (the item is the number zero; the clause changes how it is shown) | false (the item is compared as its blank display text) | the module (COBOL-85 5.4) | **open — report to the operator**: a 1.x.x fix in `Interpreter::as_comparand` (`interpreter.rs`), which should substitute the blank text only against a character operand, as the module does. No NIST member exercises it. |
| 2 | `BLANK WHEN ZERO` numeric-edited item receiving a value that is zero only after truncation to the picture's decimals (`0.001` into `Z9.99`) | blanks | prints `0.00` (tests the value before truncation) | the module (the item's value is zero) | open, same fix as #1's family; no NIST member exercises it |

| 4 | `FUNCTION` calls, nested programs, `CALL … LINKAGE`, `EXEC`, control members | refused at build time with the construct named | run | — | open: IF and IC modules (GOLDEN RULE #9) |

| 14 | `BY REFERENCE` / `BY CONTENT` where the argument and the parameter are described differently (`PIC 9(4)` into `PIC S9(4) COMP`) | the parameter sees the argument's bytes (12336 for the text `0021`) | the parameter sees the value (21) | the module, by COBOL-85, which asks the two descriptions to agree; the interpreter keeps values, not bytes | by design (WASM-010 Q5, "answered, to confirm"): not a bug in either engine. Under the plan's working assumption Check would warn here; **no warning is emitted yet** — the `REDEFINES`/description warning (`WarningKind::RedefinesMayDiffer`) exists but has no difference to point at that is shown not to be a bug, so T13 emits none |
| 15 | `OPEN OUTPUT`, `I-O` or `EXTEND` of an INDEXED file declared `STORAGE IS MEMORY` **without** `WITH PERSISTENCE` | opens; the records live with the form instance until it closes (`cobolt_wasm_rt::idx`, WASM-010 T14). `WITH PERSISTENCE` is refused at build time: a browser module has no disk | status **37**: a memory file without `WITH PERSISTENCE` is a read-only copy (operator, 2026-10-01, `IndexedFile::open`) | neither is wrong: the desktop's rule protects data that looks saved and is not; a browser module saves nothing, and Q8 ("in-memory INDEXED files are in") and Q-new-1 (a `WRITE` the memory cannot hold is 89) only make sense if the file can be written | **working assumption, to confirm by the operator** (WASM-010 T14). | 16 | `SORT … USING`/`GIVING` on INDEXED (or any keyed) files; `MERGE` | refused at build time (`SORT` takes an `INPUT`/`OUTPUT PROCEDURE` in a browser module; `MERGE` reads files) | `SORT` reads and writes only sequential files (`read_all_records`/`write_all_records` see `OpenFile::Reader`/`Writer`): on an INDEXED file `USING` delivers no record and `GIVING` writes none, and the program is not told | the module refuses what it cannot do; the interpreter silently does nothing | open — the interpreter's silence is a 1.x.x matter (report to the operator); the module's refusal is by design |
| 17 | A `PIC N` (national) item in a group that travels as JSON | holds its text as UTF-8 bytes in its `2 × n` bytes, as every other routine of the module treats a national item (none converts to UTF-16); the limit is counted in UTF-16 units (S5), and a string whose UTF-8 bytes would not fit the `2 × n` bytes is refused `too-long` | the item holds characters; any string of at most `n` UTF-16 units is accepted | `cobolt-wire` (rule S5) | **open — generator gap**: a string of characters from U+0800 to U+FFFF (three UTF-8 bytes, one unit) filling more than two thirds of the item; the golden vectors do not reach it (WASM-010 T15). National items are bytes in the module everywhere, not only here |
| 18 | `COMPUTE r = a / 0 ON SIZE ERROR …` | the size error condition: the phrase runs, `r` is left as it was | the run stops with `RuntimeError::DivisionByZero` at the statement, the phrase notwithstanding (measured 2026-10-23; `DIVIDE … ON SIZE ERROR` by zero is handled on both) | the module (COBOL-85: a division by zero is a size error condition, and `ON SIZE ERROR` handles it) | **open — report to the operator**: a 1.x.x fix in the interpreter's `COMPUTE` (found by `crates/cobolt-wasm/tests/arith_table.rs::compute_division_by_zero_is_a_size_error`, WASM-010 T18) |
| 19 | A DataGrid bound to an INDEXED file, on a web form (WASM-005 T9) | the generated backend program reads and writes through the generated file facade with COBOL verbs: a COMP/COMP-3 field shows its **value**, a signed field shows its `-`, and Save validates every change and then writes, with **no rollback** if a write fails partway | the desktop grid shows a cell from the record's bytes (`format_field_display`: COMP/COMP-3 in hex, an overpunched sign dropped) and saves all or nothing with a rollback (`grid_unit.rs`) | neither: an accepted difference | **accepted by the operator, 2026-10-23** (WASM-005 T9, option (b); spec AC7 amended). The SQL-bound grid has no difference |
