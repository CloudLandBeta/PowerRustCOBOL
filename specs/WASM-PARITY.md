# WASM parity ledger — where a generated module and the interpreter differ

Every difference between the WebAssembly line (2.x.x) and the interpreter (1.x.x), with who is right. A difference that is the **interpreter's** defect is a fix for `main` (GOLDEN RULE #5) and is forward-ported; it is listed here until the operator decides. A difference that is deliberate stays here as the record of why.

| # | Construct | Module | Interpreter | Who is right | Status |
|---|---|---|---|---|---|
| 1 | `IF N = ZERO` where `N` is a numeric item with `BLANK WHEN ZERO` holding zero | true (the item is the number zero; the clause changes how it is shown) | false (the item is compared as its blank display text) | the module (COBOL-85 5.4) | **open — report to the operator**: a 1.x.x fix in `Interpreter::as_comparand` (`interpreter.rs`), which should substitute the blank text only against a character operand, as the module does. No NIST member exercises it. |
| 2 | `BLANK WHEN ZERO` numeric-edited item receiving a value that is zero only after truncation to the picture's decimals (`0.001` into `Z9.99`) | blanks | prints `0.00` (tests the value before truncation) | the module (the item's value is zero) | open, same fix as #1's family; no NIST member exercises it |
| 3 | Conformance builds: a record-sequential file | one record per line | fixed-length records, no separator | neither — a test-host choice; the module has no files in a browser | by design; it is why the harness tallies 4 612 `PASS` markers against the interpreter's 4 614 while every program's own summary line is identical |
| 4 | `FUNCTION` calls, nested programs, `CALL … LINKAGE`, `EXEC`, control members | refused at build time with the construct named | run | — | open: IF and IC modules (GOLDEN RULE #9) |
| 5 | `FUNCTION WHEN-COMPILED` | the time of the build (a constant in the module; `Options::when_compiled` fixes it) | the run time (same as `CURRENT-DATE`) | the module (COBOL-85: the date and time the program was compiled) | open — report to the operator: a 1.x.x fix, it should be the compile time there too; no NIST member can tell (IF142A checks the shape) |
| 6 | `FUNCTION CURRENT-DATE` offset and `ACCEPT … FROM DATE/TIME` | UTC, `+0000` (the host decides; the page may later offer local time) | the local clock with the real offset | by design — a browser module has the host's clock | by design |
| 7 | `FUNCTION MAX/MIN/SUM … (table (ALL))` over an `OCCURS … DEPENDING ON` table | uses the current count: the call record lays every element out and the count is set at run time from the counter (`rt_func_argc`, WASM-010 T13); the `ALL` must be on the outermost dimension and the last argument, or the build refuses it | **expands over the maximum** (measured 2026-10-22: `SUM (E (ALL))` with 3 of 5 occurrences gives 961, not 60) | the module (COBOL-85: `ALL` references the occurrences the counter says there are) | **generator gap closed** (2.0.35, `tests/parity_gaps.rs::all_over_a_variable_length_table_uses_its_current_count`); **interpreter: open — report to the operator**, a 1.x.x fix. No NIST member exercises it. |
| 8 | `EXIT PROGRAM` / `GOBACK` inside a `PERFORM` in a called program | leaves the program and returns to the caller (COBOL-85 6.7.4) | carries on after the `PERFORM` | the module | open — report to the operator: a 1.x.x fix (found by `crates/cobolt-wasm/tests/calls.rs::a_callee_that_returns_from_inside_a_perform`); no NIST member exercises it |
| 9 | `CALL … RETURNING` with an identifier as the program name; `BY VALUE` | each callee returns to a block of its own that moves its RETURNING item; `BY VALUE` moves the value into a copy with the parameter's own USAGE and PICTURE (WASM-010 T13) | RETURNING works; `BY VALUE` of an item works; `BY VALUE` of a **literal** reaches the callee as zero (row 12) | the module | **closed** (2.0.35, `tests/parity_gaps.rs::returning_on_a_dynamic_call_and_by_value`) |
| 10 | `PROGRAM-ID. x INITIAL` / `COMMON`; recursion; a `CALL "COBOL-…"` service | the AST keeps `INITIAL`/`COMMON` (`Program::is_initial`, `is_common`); an `INITIAL` program is put back in its initial state on every call; `COMMON` adds no restriction (every program of the module is callable by name, a superset); recursion stays refused (COBOL-85 has none); the services are classified in `support::BUILTIN_TABLE` | `COMMON` as the module; `INITIAL` ignored (row 11) | — | **closed for the generator** (2.0.35, `tests/parity_gaps.rs::common_and_initial_programs`); the interpreter's half is row 11 |
| 11 | `PROGRAM-ID. x IS INITIAL` called twice | the second call starts from the initial values (COBOL-85 6.8) | keeps the values of the first call (the parser dropped the clause until 2.0.35, and the interpreter still does not read `is_initial`) | the module | **open — report to the operator**: a 1.x.x fix (found by `tests/parity_gaps.rs::common_and_initial_programs`); no NIST member exercises it |
| 12 | `CALL x USING BY VALUE <literal>` | the callee receives the literal | the callee receives zero (measured 2026-10-22: `BY VALUE 5` into `PIC 9(2)` gives `RETURNING` 0) | the module | **open — report to the operator**: a 1.x.x fix (found by `tests/parity_gaps.rs::returning_on_a_dynamic_call_and_by_value`) |
| 13 | A callee whose `RETURNING` item is in its LINKAGE SECTION | run-time error 1107 (a LINKAGE item the CALL did not pass): the module binds only `USING` parameters | not measured | — | **open — generator gap** (found writing T13's test; the test declares the RETURNING items in WORKING-STORAGE) |
| 14 | `BY REFERENCE` / `BY CONTENT` where the argument and the parameter are described differently (`PIC 9(4)` into `PIC S9(4) COMP`) | the parameter sees the argument's bytes (12336 for the text `0021`) | the parameter sees the value (21) | the module, by COBOL-85, which asks the two descriptions to agree; the interpreter keeps values, not bytes | by design (WASM-010 Q5, "answered, to confirm"): not a bug in either engine. Under the plan's working assumption Check would warn here; **no warning is emitted yet** — the `REDEFINES`/description warning (`WarningKind::RedefinesMayDiffer`) exists but has no difference to point at that is shown not to be a bug, so T13 emits none |
