OPENING A DOCUMENT
==================

A document is opened by path or by a byte buffer handed over from COBOL.
Whichever way it arrives, the bytes it arrived as are the bytes it keeps.

===========

move between real pages rather than scrolling one long sheet.

BOUNDED MEMORY
==============

Only a window of decoded pages is held at once. A file larger than the
machine's memory opens, and the last page arrives as quickly as the first,
because reaching it costs one page of reading and not a scan of the rest.

CARD GRID
=========

The card grid replaces the document with a wall of pages. How many fit on a
row follows the card size and the width of the control itself, and nothing
else. Resizing the window does not change it.

==================

SAVE AS
=======

Save As writes the original bytes, unchanged. What is on screen was computed
from those bytes and never replaced them, so the copy is byte for byte the
file that was opened.

STREAMED CONVERSATIONS
======================

In streamed layout the control shows one pane and no chrome at all. Content
is appended as it arrives. Each chunk keeps its own form, and the stream is
assembled from them on demand.

HISTORY
=======

A past conversation is remembered as an identifier and a title, never as its
text. Choosing one asks the program for the content, which is what keeps a
long session from growing without limit.
