## 4. Unverified, and do not record otherwise

**The Windows 11 fix (1.61.140) has never run on Windows.** A user on a clean
Windows 11 install had the IDE die at `0xc0000005` printing nothing. eframe
renders through wgpu, which reaches for Vulkan first on Windows; a fresh install
has no vendor GPU driver and so no working Vulkan ICD, and the process is killed
inside driver code before anything can be reported. Windows now asks for DX12
(present even with Microsoft's inbox driver), GL behind it, `WGPU_BACKEND` still
overriding.

It is reasoned from the crash trace and pinned by tests, but **nobody has
confirmed the IDE actually starts on that machine.** Ask that user before RC3 —
it is the fix most likely to matter to people who will never file a report.

The one-line check that confirms the diagnosis on the OLD build:
`set WGPU_BACKEND=dx12` before launching.

## 7. Decisions worth not re-litigating

* **The bar for "feature" is very high here.** The operator has now corrected the
  classification four times, always the same way. The test: *was the capability
  implied by something already shipped?* Then finishing it is a **fix**, however
  much new code it takes. A control in the toolbox promises everything a
  developer would expect it to do; **machinery that visibly reacts has already
  made the promise** (Cmd+click highlighted the control but never completed the
  selection — still a fix). Even a brand-new dialog *and* installer action (the
  Rust check) was ruled a fix. Say which you think it is and expect "fix".
* **Shared files beat a perfect commit split.** When CHANGELOG.md and version.rs
  are touched by everything, the operator chose two commits (one fixes, one
  features) over carving hunks. Note the impurity in the message rather than
  chasing purity.
* **`origin/main` has branch protection** ("must not contain merge commits") that
  the operator's account **bypasses**. `--no-ff` merges push through with a
  "Bypassed rule violations" notice. Normal here, and it matches the history —
  but whether main should be linear is still undecided.

## 8. Traps this session paid for

**A reproduction that cannot fail is worse than none.**
`control_pointer_events` emits `onClick` (and the other universal pointer events)
**only for a control that BINDS a handler**. A test control from
`ctrl(...)`/`ctrlp(...)` has no bindings, so it receives no `onClick` at all. I
built three harness scenes for a double-firing Switch — plain window, inside a
Panel, shell-hosted with a SideMenu — and all three reported "one event". All
three used an unbound Switch and were structurally incapable of showing the bug.
I reported "cannot reproduce" three times on that evidence. Use
`ctrlp_events(..., &["onClick"])` or `c.ensure_event("onClick")`, and prove the
guard goes RED on the unfixed code.

**Instrument the real process; write to a FILE.** What settled it was
`COBOLT_EVENT_TRACE` (Help ▸ Debug Settings ▸ Events, or the env var): one line
per event at both ends of the channel — the host's `send`, the interpreter's
`dispatch` — interleaved with the program's own DISPLAY on one timeline. Order is
the signal. My first version wrote to stderr only, which lands in the operator's
terminal — the one place Claude cannot read — and cost two round trips.
`std::env::temp_dir()` is **`$TMPDIR` on macOS, not `/tmp`**; saying "/tmp" cost
another.

**Measure before fixing a corner.** The corner leak (1.61.135) was cracked by a
shape dump built from the operator's *real* `.cfrm` values — including a
`CornerRadius` of 51, not the 34 an earlier note assumed. The hypothesis was
right in outline and wrong about what was bleeding.

**A control is drawn by two paths** — `paint.rs` (designer) and `render.rs`
(run/preview) — and only the run form calls `restore_container_outline`. So
"artifact in the run form, clean in the RAD" points straight at the restore. That
asymmetry is diagnostic; ask which surface, or read the two call sites.

**Anything that both PAINTS a stack and is later SAMPLED gets one definition.**
Shadows now build their layers through one `ShadowStack` used by the painter and
the notch mask; boolean property text goes through one `canonical_prop_value`
used by both write paths. Every drift bug this session was two derivations of one
thing.
